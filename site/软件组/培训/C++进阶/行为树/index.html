行为树（Behavior Tree）

行为树是一种用于组织机器人控制逻辑的树形决策结构，将复杂的控制流程拆解为可组合、可复用的节点，替代传统的 if-else 嵌套或状态机写法。

1. 概念——为什么需要行为树？

1.1 传统写法的问题

假设你要写一段底盘控制逻辑：如果倒地就自起，否则根据信号执行上台阶/跳跃/常规运动。用传统的 if-else + switch 会写成：

void controlLoop() {
    if (isFallen()) {
        recoveryStateMachine();  // 自起状态机，可能跨多个周期
    } else {
        if (stairSignal()) {
            stairClimbing();
        } else if (jumpSignal()) {
            jumpStateMachine();
        } else {
            remoteTargetSetting();
        }
        balanceLQR();
        turnControl();
        powerControl();
        antiSplitCompensation();
        legLengthControl();
        rollControl();
        legVMC();
    }
}

这段代码存在以下问题：

问题 说明
逻辑扁平化 所有逻辑挤在一个函数里，新增功能需要修改核心流程
多周期状态散落 自起、跳跃等跨周期的状态机需要额外的 static 变量或成员变量来追踪进度
优先级不直观 倒地检测必须在最前面，但代码结构上没有强制这一点——删一行、调个顺序就可能出 bug
复用困难 想把"倒地检测 → 自起"这套逻辑搬到另一个机器人上，需要手动复制粘贴

1.2 行为树的解决思路

行为树把控制逻辑组织成一棵树，每个节点只做一件事，树的形状本身就表达了优先级和依赖关系。同样的逻辑用行为树表达：

Root [Selector: 二选一]
├── 倒地自起 [Sequence: 两个都成功才成功]
│   ├── 倒地检测 [Condition]
│   └── 自起状态机 [Action]
│
└── 默认运动控制 [Sequence: 全部依次执行]
    ├── 动作模式选择 [Selector: 三选一]
    │   ├── 上台阶 [Sequence]
    │   │   ├── 上台阶信号检测 [Condition]
    │   │   └── 上台阶执行 [Action]
    │   ├── 跳跃 [Sequence]
    │   │   ├── 跳跃信号检测 [Condition]
    │   │   └── 跳跃状态机 [Action]
    │   └── 常规遥控目标设定 [Action]
    ├── 平衡控制 LQR [Action]
    ├── 转向控制 PID [Action]
    ├── 功率控制 [Action]
    ├── 防劈叉补偿 PID [Action]
    ├── 腿长与姿态控制 [Sequence]
    │   ├── 腿长控制 PID [Action]
    │   └── Roll 控制 PID [Action]
    └── 腿部控制 VMC [Action]

树的结构本身就是文档——你一眼就能看出： - 倒地自起优先级最高（放在 Selector 的第一个子节点） - 默认运动控制的 7 个 Action 是串行依赖的 - 上台阶、跳跃、常规遥控是三选一的关系

2. 三状态协议——一切节点的基础

行为树中每个节点的 tick() 方法必须返回三种状态之一：

enum class BTStatus : uint8_t {
    BT_SUCCESS, // 成功
    BT_FAILURE, // 失败
    BT_RUNNING  // 运行中（还没做完，下个周期继续）
};
状态 含义 示例场景
BT_SUCCESS 本周期任务完成 条件满足、动作一步到位
BT_FAILURE 任务失败或条件不满足 倒地检测未触发、PID 计算异常
BT_RUNNING 任务进行中，下个周期继续 自起状态机还在 Phase1、跳跃还在起跳阶段

BT_RUNNING 是行为树区别于普通函数调用的关键——它让跨周期的长流程可以自然地嵌入树中，不需要额外的全局状态机变量。

3. 节点类型——四大类

GSRL 行为树定义了三类基础节点 + 一个管理类：

BTNode（抽象基类）
│
├── BTComposite<MaxChildren>（组合节点——有多个子节点）
│   ├── BTSequence（顺序节点）
│   └── BTSelector（选择节点）
│
├── BTDecorator（修饰节点——只有一个子节点）
│   ├── BTInverter（取反）
│   ├── BTRepeat（重复）
│   ├── BTForceSuccess（强制成功）
│   └── BTForceFailure（强制失败）
│
├── BTAction（行为节点——叶子，调用回调函数）
└── BTCondition（条件节点——叶子，判断 bool）

3.1 组合节点基类：BTComposite

template <uint8_t MaxChildren = BT_DEFAULT_MAX_CHILDREN>  // 默认最多 16 个子节点
class BTComposite : public BTNode {
protected:
    BTNode *m_children[MaxChildren];  // 子节点指针数组
    uint8_t m_childCount = 0;         // 当前子节点数量

public:
    // 添加子节点——按添加顺序执行
    bool addChild(BTNode *child) {
        if (child == nullptr || m_childCount >= MaxChildren) return false;
        m_children[m_childCount++] = child;
        return true;
    }

    void reset() override {
        for (uint8_t i = 0; i < m_childCount; i++)
            m_children[i]->reset();
    }
};

关键设计：模板参数 MaxChildren 让子节点数组在编译期确定大小，用栈上数组而非 std::vector，避免了堆分配，契合嵌入式场景。

4. 核心组合节点——Sequence 与 Selector

这是行为树最重要的两个组合节点，它们定义了子节点的执行规则。

4.1 Sequence（顺序节点）——"而且"逻辑

Sequence: 依次执行子节点，像一个"串联电路"
┌──→ Child0 ──→ Child1 ──→ Child2 ──→ SUCCESS
│      ↓Fail      ↓Fail      ↓Fail
│    FAILURE    FAILURE    FAILURE
│      ↓Running   ↓Running   ↓Running
│    RUNNING    RUNNING    RUNNING

规则：所有子节点都返回 SUCCESS，Sequence 才返回 SUCCESS。任一子节点返回 FAILURE，立即终止；任一返回 RUNNING，暂停并记住位置。

源码：

template <uint8_t MaxChildren>
class BTSequence : public BTComposite<MaxChildren> {
private:
    uint8_t m_runningIndex = 0;  // 记录上次 RUNNING 的子节点索引

public:
    BTStatus tick() override {
        for (uint8_t i = m_runningIndex; i < this->m_childCount; i++) {
            BTStatus status = this->m_children[i]->tick();
            if (status == BTStatus::BT_FAILURE) {
                m_runningIndex = 0;        // 重置，下次从头开始
                return BTStatus::BT_FAILURE;
            }
            if (status == BTStatus::BT_RUNNING) {
                m_runningIndex = i;        // 记住位置，下周期从此处继续
                return BTStatus::BT_RUNNING;
            }
        }
        m_runningIndex = 0;
        return BTStatus::BT_SUCCESS;
    }
};

m_runningIndex 的作用：当子节点返回 RUNNING 时记录索引，下个周期 tick() 直接从该索引继续，而不是重新从头执行。这保证了跨周期的状态连续性。

使用场景：有一系列必须按顺序完成的操作。

// 默认运动控制：7 个控制步骤必须依次完成
BTSequence<7> m_defaultMotionControl;
m_defaultMotionControl.addChild(&m_actionModeSelector);   // 1. 先决定做什么动作
m_defaultMotionControl.addChild(&m_balanceLQR);            // 2. 再跑平衡控制
m_defaultMotionControl.addChild(&m_turnControl);           // 3. 转向
m_defaultMotionControl.addChild(&m_powerControl);          // 4. 功率
m_defaultMotionControl.addChild(&m_antiSplitCompensation); // 5. 防劈叉
m_defaultMotionControl.addChild(&m_legLengthAndPosture);   // 6. 腿长+姿态
m_defaultMotionControl.addChild(&m_legVMC);                // 7. 腿部 VMC

4.2 Selector（选择节点）——"或者"逻辑

Selector: 依次尝试子节点，像一个"并联电路"——哪个通就用哪个
┌──→ Child0 ──→ Child1 ──→ Child2 ──→ FAILURE
│      ↓Success   ↓Success   ↓Success
│    SUCCESS    SUCCESS    SUCCESS

规则：任一子节点返回 SUCCESS，Selector 立即返回 SUCCESS。全部返回 FAILURE 才返回 FAILURE。

源码：

template <uint8_t MaxChildren>
class BTSelector : public BTComposite<MaxChildren> {
private:
    uint8_t m_runningIndex = 0;

public:
    BTStatus tick() override {
        for (uint8_t i = m_runningIndex; i < this->m_childCount; i++) {
            BTStatus status = this->m_children[i]->tick();
            if (status == BTStatus::BT_SUCCESS) {
                m_runningIndex = 0;
                return BTStatus::BT_SUCCESS;
            }
            if (status == BTStatus::BT_RUNNING) {
                m_runningIndex = i;
                return BTStatus::BT_RUNNING;
            }
        }
        m_runningIndex = 0;
        return BTStatus::BT_FAILURE;
    }
};

使用场景：多个互斥选项按优先级排列。

// 动作模式——优先级递减：上台阶 > 跳跃 > 常规遥控
BTSelector<3> m_actionModeSelector;
m_actionModeSelector.addChild(&m_stairClimbing);    // 优先尝试上台阶
m_actionModeSelector.addChild(&m_jumpControl);      // 其次尝试跳跃
m_actionModeSelector.addChild(&m_remoteTargetSetting); // 都不行就常规遥控

关键理解：Selector 的子节点顺序决定了优先级——序号越小的子节点越优先被执行。这就是行为树自带"优先级决策"的能力。

4.3 Sequence + Selector 的组合模式

基础的树结构几乎都遵循这个模式：

Selector（高层决策：选择"哪种模式"）
├── Sequence（模式A：条件 + 执行）
│   ├── Condition（条件检测）
│   └── Action（执行）
├── Sequence（模式B：条件 + 执行）
│   ├── Condition
│   └── Action
└── Action（兜底默认行为）

一个真实例子：

// Root：倒地检测优先，否则走正常流程
BTSelector<2> m_root;
m_root.addChild(&m_groundRecovery);      // 如果"倒地检测→自起"那条 Sequence 成功，走这里
m_root.addChild(&m_defaultMotionControl); // 否则走正常的 7 步 Sequence

// 倒地自起是一个 Sequence：条件满足才执行
BTSequence<2> m_groundRecovery;
m_groundRecovery.addChild(&m_fallDetection);       // Condition：是否倒地？
m_groundRecovery.addChild(&m_recoveryStateMachine); // Action：是的话自起

5. 修饰节点——对子节点结果做变换

修饰节点只有一个子节点，不改变子节点的行为，只修改子节点的返回值。适用于对已有节点进行逻辑变换，无需重写节点逻辑。

class BTDecorator : public BTNode {
protected:
    BTNode *m_child;  // 唯一的子节点
public:
    BTDecorator(BTNode *child);
    void reset() override {
        if (m_child != nullptr) m_child->reset();
    }
};

5.1 BTInverter（取反）

Inverter{
    child→SUCCESS  → FAILURE
    child→FAILURE  → SUCCESS
    child→RUNNING  → RUNNING  (不变)
}

使用场景：把"敌人不在视野"变成一个可用的 Condition。

// "没有检测到敌人" = 对"检测到敌人"取反
BTCondition enemyDetected(isEnemyVisible, &context);
BTInverter noEnemy(&enemyDetected);  // 取反后可作为巡逻的条件

5.2 BTRepeat（重复）

让子节点重复执行指定次数：

BTRepeat(BTNode *child, uint32_t maxCount = 0);
// maxCount = 0 → 无限重复（每次 SUCCESS 后重置，继续下一轮）
// maxCount = N → 重复 N 次后返回 SUCCESS

5.3 BTForceSuccess / BTForceFailure

ForceSuccess{
    child→SUCCESS/Failure → SUCCESS  (全部强制成功)
    child→RUNNING         → RUNNING  (不变)
}

ForceFailure{
    child→SUCCESS/Failure → FAILURE  (全部强制失败)
    child→RUNNING         → RUNNING  (不变)
}

使用场景：某个 Action 即使失败了也不影响整体流程——用 BTForceSuccess 包裹它。

6. 叶子节点——Action 与 Condition

叶子节点是行为树的末端，不包含任何子节点。通过函数指针回调将具体逻辑注入节点对象。

6.1 BTCondition（条件节点）

检查一个布尔条件，返回 SUCCESS 或 FAILURE（绝不返回 RUNNING）。

class BTCondition : public BTNode {
public:
    using ConditionFunc = bool (*)(void *context);
private:
    ConditionFunc m_condition;
    void *m_context;
public:
    BTCondition(ConditionFunc condition, void *context = nullptr);
    BTStatus tick() override {
        if (m_condition != nullptr && m_condition(m_context))
            return BTStatus::BT_SUCCESS;
        return BTStatus::BT_FAILURE;
    }
};

使用方式：

// 定义回调函数
static bool fallDetectionCallback(void *context) {
    auto *self = static_cast<ChassisBehaviorTree *>(context);
    // 读取传感器数据，判断是否倒地
    auto *chassis = self->m_chassis;
    return (chassis->phi0 < 0.0f || chassis->imuPitch < -PI / 4);
}

// 构造条件节点，将 this 指针作为 context 传入
BTCondition m_fallDetection(fallDetectionCallback, this);

6.2 BTAction（行为节点）

执行一个动作，可以返回三种状态中的任意一种。

class BTAction : public BTNode {
public:
    using ActionFunc = BTStatus (*)(void *context);
private:
    ActionFunc m_action;
    void *m_context;
public:
    BTAction(ActionFunc action, void *context = nullptr);
    BTStatus tick() override {
        if (m_action != nullptr)
            return m_action(m_context);
        return BTStatus::BT_FAILURE;
    }
};

BT_RUNNING 在 Action 中的典型用途——状态机跨周期：

// 自起状态机在 Phase1 翻倒自正阶段，需要多个周期完成
static BTStatus recoveryStateMachineCallback(void *context) {
    auto *self = static_cast<ChassisBehaviorTree *>(context);

    switch (self->m_recoveryPhase) {
    case RECOVERY_PHASE1_FLIP:
        // 持续旋转腿部翻转机体
        self->m_targetPhi0Left += 0.1f;
        if (fabs(self->m_targetPhi0Left) < PI)
            return BTStatus::BT_RUNNING;  // 还没转完，下周期继续
        self->m_recoveryPhase = RECOVERY_PHASE2_POSITION;
        return BTStatus::BT_RUNNING;      // 进入下一阶段

    case RECOVERY_PHASE2_STANDUP:
        // 快速移动 phi0 至 π/2
        self->m_targetPhi0Left = PI / 2;
        if (fabs(chassis->phi0 - PI / 2) > 0.05f)
            return BTStatus::BT_RUNNING;  // 还在移动
        self->m_recoveryPhase = RECOVERY_INIT;
        return BTStatus::BT_SUCCESS;      // 自起完成！
    }
}

6.3 context 指针的设计

BTAction 和 BTCondition 都接受一个 void *context 参数。这个设计允许：

  • 回调函数访问外部对象（如 Chassis 实例、传感器数据）
  • 同一回调函数被多个树实例复用
  • 不依赖全局变量

GMaster 中的标准做法——构造节点时传入 this：

m_fallDetection(fallDetectionCallback, this),
m_recoveryStateMachine(recoveryStateMachineCallback, this),

回调函数内部通过 static_cast 还原类型：

static bool fallDetectionCallback(void *context) {
    auto *self = static_cast<ChassisBehaviorTree *>(context);
    auto *chassis = self->m_chassis;
    return chassis->phi0 < 0.0f;
}

7. BehaviorTree——树的运行时管理

BehaviorTree 是整棵树的管理类，封装了 tick() 和 reset()：

class BehaviorTree {
private:
    BTNode *m_root;
public:
    BehaviorTree(BTNode *root = nullptr);
    void setRoot(BTNode *root);
    BTStatus tick();    // 执行一次整棵树
    void reset();       // 重置所有节点状态
};

tick() 的实现很简单——把调用委托给根节点：

BTStatus BehaviorTree::tick() {
    if (m_root != nullptr)
        return m_root->tick();
    return BTStatus::BT_FAILURE;
}

从根节点开始递归 tick()，结果由树的层级结构自然传播——这就是行为树"自上而下决策、自下而上反馈"的核心机制。

8. 完整实例——组装一棵底盘行为树

以下是 ChassisBehaviorTree::init() 的完整代码，展示了从叶子到根节点的组装过程：

void ChassisBehaviorTree::init(Chassis *chassis) {
    m_chassis = chassis;

    // ===== 第 1 层：叶子节点（已在构造函数中创建） =====
    // 不再重复创建，直接引用成员变量

    // ===== 第 2 层：构建小组合 =====

    // 倒地自起 [Sequence<2>]: 检测 → 执行
    m_groundRecovery.addChild(&m_fallDetection);
    m_groundRecovery.addChild(&m_recoveryStateMachine);

    // 上台阶 [Sequence<2>]: 检测 → 执行
    m_stairClimbing.addChild(&m_stairClimbingCondition);
    m_stairClimbing.addChild(&m_stairClimbingAction);

    // 跳跃 [Sequence<2>]: 检测 → 执行
    m_jumpControl.addChild(&m_jumpCondition);
    m_jumpControl.addChild(&m_jumpStateMachine);

    // 腿长与姿态 [Sequence<2>]: 腿长 PID → Roll PID
    m_legLengthAndPosture.addChild(&m_legLengthControl);
    m_legLengthAndPosture.addChild(&m_rollControl);

    // ===== 第 3 层：动作模式选择 =====

    // 动作模式选择 [Selector<3>]: 上台阶 | 跳跃 | 常规遥控
    m_actionModeSelector.addChild(&m_stairClimbing);
    m_actionModeSelector.addChild(&m_jumpControl);
    m_actionModeSelector.addChild(&m_remoteTargetSetting);

    // ===== 第 4 层：默认运动控制 =====

    // 默认运动控制 [Sequence<7>]
    m_defaultMotionControl.addChild(&m_actionModeSelector);
    m_defaultMotionControl.addChild(&m_balanceLQR);
    m_defaultMotionControl.addChild(&m_turnControl);
    m_defaultMotionControl.addChild(&m_powerControl);
    m_defaultMotionControl.addChild(&m_antiSplitCompensation);
    m_defaultMotionControl.addChild(&m_legLengthAndPosture);
    m_defaultMotionControl.addChild(&m_legVMC);

    // ===== 第 5 层：根节点 =====

    // Root [Selector<2>]: 倒地自起 | 默认运动控制
    m_root.addChild(&m_groundRecovery);
    m_root.addChild(&m_defaultMotionControl);
}

每一步操作 addChild() 都在"声明节点之间的关系"——组装完成后，树的结构直接映射到机器人控制逻辑，无需额外的调度代码。

9. 运行机制——一次 tick 的全过程

假设机器人当前处于正常站立状态（没有倒地，也没有触发跳跃/上台阶），一次 tick() 的执行流程如下：

m_tree.tick()
  │
  └── m_root.tick()  [Selector<2>]
        │
        ├── m_groundRecovery.tick()  [Sequence<2>]
        │     ├── m_fallDetection.tick()  → BT_FAILURE (没倒地)
        │     └── return BT_FAILURE      (Sequence 遇 Fail，立即终止)
        │
        ├── 第一个子节点返回 FAILURE，Selector 继续尝试下一个
        │
        └── m_defaultMotionControl.tick()  [Sequence<7>]
              ├── m_actionModeSelector.tick()  [Selector<3>]
              │     ├── m_stairClimbing.tick()  → BT_FAILURE
              │     ├── m_jumpControl.tick()    → BT_FAILURE
              │     └── m_remoteTargetSetting.tick()  → BT_SUCCESS  ✓
              │     return BT_SUCCESS
              │
              ├── m_balanceLQR.tick()           → BT_SUCCESS  ✓
              ├── m_turnControl.tick()          → BT_SUCCESS  ✓
              ├── m_powerControl.tick()         → BT_SUCCESS  ✓
              ├── m_antiSplitCompensation.tick()→ BT_SUCCESS  ✓
              ├── m_legLengthAndPosture.tick()
              │     ├── m_legLengthControl.tick() → BT_SUCCESS  ✓
              │     └── m_rollControl.tick()      → BT_SUCCESS  ✓
              │     return BT_SUCCESS
              │
              └── m_legVMC.tick()               → BT_SUCCESS  ✓
              return BT_SUCCESS

关键观察： - 树的层级结构天然决定了执行路径——不需任何 if-else - Condition 节点（m_fallDetection、m_stairClimbingCondition）起到"门控"作用 - Selector 的优先级机制让高优先级行为（倒地自起）先于低优先级（常规遥控）

11. 使用原则

场景 做法 原因
互斥选择（优先级） Selector 子节点按优先级排列，遇 Success 即返回
串行依赖（A → B → C） Sequence 前一步失败则整体失败，前一步 RUNNING 则暂停
条件 + 执行 Sequence(Condition, Action) 条件不满足则不执行
跨周期长流程 Action 返回 BT_RUNNING 保留内部状态，下个 tick 自动续接
修改已有节点行为 用 BTDecorator 包裹 Inverter 取反、ForceSuccess 屏蔽失败
需要复用同一回调 利用 void *context 不同 context 指针注入不同对象
需要日志/调试 用 BTForceSuccess 包裹 确保某个节点的失败不中断后续流程

12. 与 GSRL 的关系

  • 嵌入式适配：BTComposite 使用栈上定长数组（模板参数 MaxChildren），不依赖 std::vector，避免堆分配。
  • 函数指针回调：BTAction / BTCondition 使用函数指针 + void *context（而非 std::function），避免动态内存和虚表开销。
  • 实际应用场景：当前行为树在 26UC-chassis（级联腿步兵底盘）中被用于管理倒地自起、上台阶、跳跃、常规运动控制等逻辑。
  • 与 FreeRTOS 的关系：行为树不是替代 FreeRTOS 任务，而是任务内部的控制逻辑组织方式。在 tsk_gimbal.cpp 中，FreeRTOS 任务以 1ms 周期调用 gimbal.controlLoop()，行为树取代了 controlLoop() 内部传统的 if-else 调度。

13. 总结

概念 一句话
行为树 树形结构组织控制逻辑，替代平铺的 if-else
BTStatus 三态：SUCCESS / FAILURE / RUNNING
Sequence "而且"——全部成功才成功，遇失败即终止
Selector "或者"——哪个成功用哪个，按优先级排列
BTDecorator 包装一个子节点，修改其返回值
BTAction 叶子，执行回调，可返回 RUNNING 表示跨周期
BTCondition 叶子，判断条件，只返回 SUCCESS 或 FAILURE
BehaviorTree 管理器，tick() 从根节点递归执行整棵树
