# 函数：把一段逻辑封装起来复用

前面几章写的代码都堆在 `main` 里，一行接一行地执行。程序一旦长起来，这种写法就撑不住了：几百行代码挤在一处，既难读懂，也难修改，更谈不上复用。函数就是为解决这个问题而生的——它把一段完成特定任务的逻辑封装成一个带名字的单元，需要时按名字调用即可。

## 函数解决的根本问题

设想 `main` 里塞进了几百行代码：先是一百行验证输入，接着两百行计算，再是五十行输出。读的人得从头看到尾才明白它在做什么，改的人也不敢轻易下手。

```c
int main()
{
    // 100 行验证输入的代码
    // 200 行计算逻辑
    // 50 行输出结果
    // ——难以阅读、难以修改、难以复用
}
```

把这几段各自封装成函数后，`main` 的意图便一目了然：

```c
int main()
{
    int input = get_valid_input();
    int result = calculate(input);
    print_result(result);
}
```

函数带来的价值有三点：把实现细节藏进函数内部，用名字表达这段代码要做什么，以及在多处重复使用同一段逻辑而不必抄写。

## 函数的组成

一个函数由返回类型、函数名、参数列表和函数体四部分构成。返回类型说明函数算完会交回什么类型的结果，不返回任何东西时写 `void`；函数名描述它做什么，通常是个动词；参数列表是调用者传进来的数据；函数体是花括号里真正执行的逻辑。

```c
int add(int a, int b)
{
    int sum = a + b;
    return sum;
}
```

这个 `add` 接收两个 `int`，返回它们的和。`return` 把结果交回给调用它的地方。

## 声明与定义

C 语言要求函数在被调用之前，编译器已经知道它的存在，否则编译器读到调用处时并不认识这个名字。满足这个要求有两种做法。

一种是把定义写在调用之前，编译器读到调用时函数体已经出现过。

```c
#include <stdio.h>

int add(int a, int b)
{
    return a + b;
}

int main()
{
    int result = add(3, 5);
    printf("%d\n", result);
    return 0;
}
```

另一种更常用：先在文件顶部写一行函数声明，也叫函数原型，只交代函数的签名而不写函数体，具体定义留到后面，甚至放在另一个 `.c` 文件里。

```c
#include <stdio.h>

int add(int a, int b);   // 声明：只有签名，没有函数体

int main()
{
    int result = add(3, 5);   // 编译器已经见过声明，允许调用
    printf("%d\n", result);
    return 0;
}

int add(int a, int b)         // 定义可以放在后面
{
    return a + b;
}
```

声明里的参数名可以省掉，写成 `int add(int, int);` 也能通过编译，但留着名字更便于阅读。

## 参数是怎么传进去的

C 语言默认按值传递。函数拿到的是实参的一份副本，在函数内改动这个副本，外面的原变量丝毫不受影响。

```c
void increment(int x)
{
    x = x + 1;               // 改的只是副本
    printf("函数内：%d\n", x);
}

int main()
{
    int n = 10;
    increment(n);
    printf("函数外：%d\n", n);   // 仍然是 10
    return 0;
}
// 输出：
// 函数内：11
// 函数外：10
```

想让函数真正改到外部的变量，就得把那个变量的地址传进去。函数拿到地址后，顺着地址找回原变量本身，改动便落在原处。这一步用到了指针，指针会在后面的章节详细展开，此处先建立一个印象：传地址，函数就能改到外面的东西。

```c
void increment(int* p)
{
    *p = *p + 1;             // 顺着地址改原变量
}

int main()
{
    int n = 10;
    increment(&n);           // 传入 n 的地址
    printf("%d\n", n);       // 11
    return 0;
}
```

传值和传指针的区别，本质上是"给不给函数改动原数据的权力"：

| 传递方式 | 函数内的修改 | 适用场景 |
|----------|-----------|----------|
| 传值 `void f(int x)` | 不影响原变量 | 只需读取数据 |
| 传指针 `void f(int* p)` | 影响原变量 | 需要修改数据，或传递大块数据以避免整份拷贝 |

数组作为参数时有个需要留心的特点：它不会整个拷贝进去，而是退化成一个指针，函数收到的只是首元素的地址。

```c
void print_array(int arr[], int size)   // arr 实际上是一个指针
{
    for (int i = 0; i < size; i++) {
        printf("%d ", arr[i]);
    }
}
```

正因为传进去的只是地址，函数内部并不知道数组有多长，所以必须额外传一个长度参数。在函数里对 `arr` 用 `sizeof`，得到的是指针的大小（通常 4 或 8 字节），而不是数组的实际大小。

## 返回值

`return` 做两件事：把结果交回调用者，同时立即结束当前函数。一旦执行到 `return`，它后面的代码就不再运行，这个特性常用来在出错时提前退出。

```c
int divide(int a, int b, int* result)
{
    if (b == 0) {
        return 0;              // 除数为 0，立即返回，后面不执行
    }
    *result = a / b;
    return 1;                  // 正常算完
}
```

如果一个函数只是做些事情而没有结果需要交回，返回类型写 `void`。这类函数末尾会自动返回，写不写 `return;` 都行。

```c
void greet(const char* name)
{
    printf("你好，%s！\n", name);
}
```

## 递归

函数调用自身，称为递归。它适合处理那种自身包含自身、结构上层层相似的问题。阶乘就是典型例子：`n` 的阶乘等于 `n` 乘以 `n-1` 的阶乘。

```c
int factorial(int n)
{
    if (n <= 1) {
        return 1;                     // 基准条件
    }
    return n * factorial(n - 1);      // 递归条件
}
```

调用 `factorial(4)` 会一层层展开，直到触底再逐层算回来：

```
factorial(4) = 4 * factorial(3)
             = 4 * 3 * factorial(2)
             = 4 * 3 * 2 * factorial(1)
             = 4 * 3 * 2 * 1
             = 24
```

递归能成立，靠的是两个缺一不可的要素：一个基准条件，作为停下来的出口；一个递归条件，让每次调用都朝基准条件靠近。少了任何一个，递归就永远停不下来。而每一层调用都要占用栈空间来保存局部变量和返回地址，层数太深会把栈耗尽，导致栈溢出（Stack Overflow）。所以对于简单的重复问题，用 `for`、`while` 循环往往比递归更省资源。

## 作用域与生命周期

变量在哪里声明，决定了它在哪里可见、能活多久。全局变量声明在所有函数之外，程序里处处可见；局部变量声明在函数内，每次调用都重新创建，函数结束就消失。还有一种静态局部变量，用 `static` 修饰，它虽然写在函数里，值却能在多次调用之间保留下来。

```c
int global = 100;             // 全局变量，所有函数可见

void foo()
{
    static int call_count = 0;  // 静态局部变量，跨调用保留
    call_count++;
    printf("foo 被调用了 %d 次\n", call_count);

    int local = 10;             // 普通局部变量，每次调用重建
}

int main()
{
    foo();   // foo 被调用了 1 次
    foo();   // foo 被调用了 2 次
    foo();   // foo 被调用了 3 次
    return 0;
}
```

## 几个容易踩的坑

写函数时反复出现的错误，多半和前面讲的机制对不上。忘了前置声明，就会在调用处报错，补一行原型即可。期望 `f(x)` 之后 `x` 被改动，却用了传值参数，这时该换成指针参数 `f(&x)`。把数组传进函数后还想用 `sizeof(arr)` 求长度，得到的却是指针大小，必须额外传长度。递归少了基准条件会无限递归撑爆栈。

其中最隐蔽的一个，是返回局部变量的地址。

```c
int* bad()
{
    int x = 42;
    return &x;   // 危险：x 是局部变量，函数返回后它的内存已经失效
}
```

`x` 在函数结束时就被销毁了，它的地址随即指向一块无效内存。调用者拿着这个地址去访问，得到的是不可预料的结果。要交回数据，应该返回值本身，或者使用 `static`、动态分配这类生命周期更长的存储。

设计函数时，几条朴素的原则能让代码更好维护：一个函数只做一件事；名字表达它做什么而非怎么做；参数别太多，超过四个就考虑打包成结构体；能不改动外部状态就不改；长度控制在一屏之内，便于一眼看懂。

| 原则 | 说明 | 反面示例 |
|------|------|----------|
| 单一职责 | 一个函数只做一件事 | `calculate_and_print_and_save()` |
| 命名表意图 | 函数名描述做什么，而非怎么做 | `procData()` 应改为 `filter_valid_records()` |
| 参数宜少 | 超过 4 个参数考虑封装为结构体 | `void draw(int, int, int, int, int, int, char*)` |
| 无副作用 | 能不修改外部状态就不修改 | `get_count()` 内部却修改全局变量 |
| 长度适中 | 一屏内约 20-50 行 | 200 行的单一函数 |
