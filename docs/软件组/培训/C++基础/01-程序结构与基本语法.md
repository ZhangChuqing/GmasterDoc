# 程序结构与基本语法

任何一门语言的第一课，都是先认识一段能跑起来的完整程序长什么样。这一章的目的，就是把 C 程序的骨架讲清楚：一个程序由哪些部分构成，编译器又是如何把这些文字变成能执行的东西。

## 从第一个程序说起

几乎所有教材都从这段代码开始，它做的事只有一件——在屏幕上打印一行文字。

```c
#include <stdio.h>

int main()
{
    printf("Hello, World!\n");
    return 0;
}
```

短短几行，已经包含了 C 程序的全部要素。开头的 `#include <stdio.h>` 引入了标准输入输出头文件，正是它让下面的 `printf` 可用。`int main()` 是程序的入口函数，操作系统运行一个程序时，总是从 `main` 开始执行，一对花括号 `{ }` 圈出了这个函数的范围。里面的 `printf("Hello, World!\n");` 调用库函数输出文本，末尾的 `\n` 代表换行。最后的 `return 0;` 向操作系统返回一个 0，表示程序正常结束。

## 程序的骨架

把上面的例子抽象一下，一个 C 源文件大致按这样的顺序排布：最上方是 `#include` 预处理指令，用来引入头文件；接着可以有全局变量或宏定义，它们在整个文件里都可见；然后是 `main` 函数，这是程序唯一的入口，语句在其中被逐条执行；`main` 之外还可以定义其他函数，供 `main` 或彼此调用。

```
┌─────────────────────────────┐
│  #include 预处理指令          │  ← 引入头文件
├─────────────────────────────┤
│  全局变量 / 宏定义（可选）     │  ← 整个文件可见的数据
├─────────────────────────────┤
│  int main()                 │  ← 唯一的入口点
│  {                          │
│      语句;                   │  ← 逐条执行
│      return 0;              │
│  }                          │
├─────────────────────────────┤
│  其他函数定义（可选）          │  ← 供 main 或其他函数调用
└─────────────────────────────┘
```

有几条规则贯穿其中，值得一开始就记牢。一个程序有且仅有一个 `main` 函数，它是执行的起点。每一条语句都以分号 `;` 结尾，C 语言正是靠分号来判断一条语句在哪里结束，漏掉分号会直接导致编译错误。C 语言区分大小写，`Main`、`MAIN`、`main` 是三个互不相同的标识符。至于空格、换行、制表符这类空白字符，编译器会忽略多余的部分，它们不影响语义，但合理的缩进对人阅读代码至关重要。

## 注释

注释是写给人看的文字，编译器会完全忽略它。C 语言有两种写法：`//` 之后到行尾是单行注释（C99 起支持），`/* */` 之间则是可以跨越多行的块注释，但块注释不能嵌套。

```c
// 这是单行注释（C99 起支持）

/*
 * 这是多行注释
 * 可以跨越多行
 * 不可嵌套（/* 里面再写 */ 会出错）
 */

int x = 10;  // 行尾注释，解释这行代码的意图
```

注释真正的价值在于说明代码"为什么这么做"，因为意图是代码本身传达不出来的。至于"做了什么"，复杂的逻辑值得解释一句，而像 `x = 10;` 这样一目了然的语句再配上一句"把 10 赋给 x"，就纯属冗余了。

## 预处理指令

以 `#` 开头的行不是普通语句，它们在真正编译之前由预处理器先行处理。最常见的是 `#include` 和 `#define`。

```c
#include <stdio.h>    // 引入系统头文件
#include "myfile.h"   // 引入项目自定义头文件
#define PI 3.14159    // 宏定义：编译前将 PI 全部替换为 3.14159
```

`#include` 的两种写法在查找路径上有区别：尖括号 `<file.h>` 优先在系统目录中查找，多用于标准库；双引号 `"file.h"` 则先在当前目录查找，再去系统目录，多用于项目自己的头文件。`#define` 是宏定义，它会在编译前把代码里所有的 `PI` 替换成 `3.14159`，本质是纯文本替换。

## 从源码到可执行文件

写好的 `.c` 文件并不能直接运行，中间要经过一条流水线：预处理器先展开头文件和宏，编译器把处理后的代码翻译成汇编，汇编器再把汇编变成机器能懂的目标文件，最后由链接器把目标文件和用到的库拼接成一个完整的可执行文件。

```
源文件 (.c)  →  预处理  →  编译  →  汇编  →  链接  →  可执行文件
  hello.c        hello.i   hello.s  hello.o    a.out / hello.exe
```

以 GCC 为例，日常最常用的就是一步到位的编译命令，它会自动完成上述全过程：

```sh
gcc hello.c -o hello       # 编译并链接，生成可执行文件 hello
gcc -c hello.c -o hello.o  # 仅编译，生成目标文件（不链接）
gcc hello.o -o hello       # 链接目标文件，生成可执行文件
```

## 几种常见的编译错误

初学阶段遇到的报错大多集中在几处。如果链接时提示 `undefined reference to 'printf'`，通常是没有 `#include <stdio.h>` 或标准库未被链接。`expected ';' before '}'` 几乎总是上一行语句末尾漏了分号。`'main' must return 'int'` 说明 `main` 的返回类型写错了，应当是 `int` 而非 `void`。而 `implicit declaration of function` 意味着在声明或包含对应头文件之前就使用了某个函数，补上 `#include` 或前置声明即可。这些报错信息本身往往已经指明了问题所在，读懂它比盲目改代码更省时间。
