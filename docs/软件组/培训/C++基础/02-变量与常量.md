# 变量与常量：给数据起个名字

程序运行时要处理各种数据，这些数据得有地方存放。变量就是存放数据的地方——可以把它想象成一个有名字的盒子：盒子里装着一个值，名字用来找到这个盒子，往里写、从里读都通过这个名字进行。下一章讲数据类型，正是在回答这个盒子有多大、里面的东西该怎么读。这一章先把盒子本身说清楚：怎么造一个盒子，怎么用，以及一类特殊的、造好之后就不许再改的盒子——常量。

## 声明与定义

要用一个变量，先得让编译器知道它。声明是告诉编译器"有这么个名字，它是什么类型"；定义则在声明的同时真正分配出那块内存，也就是把盒子造出来。多数时候写的语句两件事一起做了。

```c
int age;            // 定义一个 int 变量 age，盒子造好了但没放东西
float score = 95.5; // 定义并初始化，造盒子的同时放进一个值
extern int count;   // 只是声明：count 的盒子在别处，这里先打个招呼
```

一个盒子如果只造出来没放东西，里面并不是空的，而是内存中残留的、无法预料的旧数据，通常叫垃圾值。局部变量不初始化就使用，是很常见的一类 bug，因为程序的行为会随着那块内存当时的内容而变，时对时错。

```c
int x;              // 造了盒子，没放值
printf("%d", x);    // 读出来的是垃圾值，输出不可预测
```

因此养成定义时就赋初值的习惯，能省去很多麻烦。

## 命名的规则

给盒子起名字不能随意。标识符只能由字母、数字和下划线组成，不能以数字开头，也不能和 C 的关键字（如 `int`、`return`）重名。此外大小写是区分的，`count` 和 `Count` 是两个不同的变量。

在合法的前提下，风格上有约定俗成的习惯：普通变量用小写加下划线的 `snake_case`，如 `motor_speed`、`max_index`；常量用全大写的 `UPPER_SNAKE_CASE`，如 `MAX_SIZE`、`PI`；循环计数器这类临时变量用单个字母 `i`、`j`、`k` 即可。这些不是语法要求，但遵循它能让代码一眼就看出哪个是变量、哪个是常量。

## 作用域与生命周期

一个变量并非在程序的任何地方都能用，它有自己的地盘，这个地盘就是作用域。规则很简单：变量从它被定义的地方开始有效，到它所在的那对大括号结束为止。

```
#include <stdio.h>

int global = 100;        // 全局变量，定义在所有函数之外，整个文件都能用

void func()
{
    int local = 10;      // 局部变量，只在 func 内部有效
}

int main()
{
    for (int i = 0; i < 5; i++)   // i 只在这个 for 循环内有效（C99 起）
    {
        int j = i * 2;            // j 只在这对大括号内有效
    }
    // 到这里 i 和 j 都已经不存在了
}
```

定义在所有函数外面的是全局变量，整个文件都能访问，配合 `extern` 还能跨文件使用，它从程序启动一直存在到结束。定义在函数或代码块内部的是局部变量，只在那对大括号里可见，进入时才诞生，离开时就销毁。生命周期和可见范围基本是一致的：盒子什么时候能用，也就是它什么时候存在。

需要留意的是同名遮蔽。如果局部变量和全局变量重名，在局部范围内局部变量优先，全局的那个被临时挡住了。这种写法不容易察觉，容易读错代码，实践中应当避免。

## 初始化与赋值

初始化和赋值看着都是"给变量一个值"，但时机不同。初始化发生在变量创建的那一刻，是往刚分配的盒子里第一次写入内容；赋值发生在变量已经存在之后，是用新值覆盖盒子里的旧值。

```c
int x = 10;     // 初始化：创建 x 的同时放入 10
x = 20;         // 赋值：x 已存在，用 20 覆盖原来的 10
```

C 里初始化有几种写法，`int a = 10;` 是最传统的一种，`int c = {30};` 是 C99 引入的统一初始化形式，它的好处是能在编译时检查出窄化转换（比如把一个放不下的大数塞进小盒子）。日常用 `=` 直接赋初值即可，关键是别让盒子空着就拿去用。

## 常量：造好就不许改的盒子

有些值在程序运行期间不应该变化，比如学生人数上限、圆周率。把它们做成常量，编译器就会替你把关，谁想修改就报错。这既表达了意图，也防止了误改。

`const` 关键字声明一个只读变量：

```c
const int MAX_STUDENTS = 50;
const double TAX_RATE = 0.13;

MAX_STUDENTS = 60;                // 编译错误，const 变量不能被修改
```

正因为不能再改，`const` 变量必须在定义时就给出初值，否则它这辈子都没机会拿到值了。

`const` 和指针搭配时要多留一分神，因为"不可改"到底指的是指针本身还是它指向的内容，取决于 `const` 写在哪里。记住一个简单的判断办法：`const` 修饰它右边最近的东西。

```c
int x = 10, y = 20;

const int* p1 = &x;    // const 在 int 左边，修饰内容：指向的值不可改，指针本身可改
p1 = &y;               // OK
*p1 = 30;              // 编译错误

int* const p2 = &x;    // const 在 * 右边，修饰指针：指针不可改，指向的值可改
*p2 = 30;              // OK
p2 = &y;               // 编译错误

const int* const p3 = &x;  // 两个都不可改
```

除了 `const`，还有两种老办法定义常量。一种是 `#define` 宏：

```c
#define PI        3.14159
#define MAX_SIZE  100
#define NAME      "GMaster"
```

宏和 `const` 有本质区别。宏是预处理阶段的纯文本替换，编译器看到代码之前，所有 `PI` 就已经被原样换成了 `3.14159`，它没有类型，不占内存，也没有作用域（从定义处一直生效到文件末尾），预处理之后宏名就消失了，调试时看不到。`const` 则是一个真正有类型的变量，编译器会做类型检查，调试时也能看到它。两相比较，日常应优先用 `const`，因为有类型检查、可调试更安全；`#define` 留给需要在编译期确定的场合，比如定义数组大小或条件编译开关。

当一组常量取的是一系列离散的、相关的整数值时，逐个写 `const` 就显得零散，用枚举 `enum` 更清晰：

```c
enum Direction {
    NORTH = 0,
    EAST  = 1,
    SOUTH = 2,
    WEST  = 3
};

enum Direction dir = NORTH;   // 语义一目了然

// 枚举默认从 0 开始逐个递增，所以上面可以简写成：
enum Status { IDLE, RUNNING, STOPPED, ERROR };
// IDLE=0, RUNNING=1, STOPPED=2, ERROR=3
```

枚举把一组相关取值收拢在一个名字下，读代码的人看到 `NORTH` 远比看到一个孤零零的 `0` 更能明白它的含义。
