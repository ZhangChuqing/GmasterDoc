# 指针：盒子的地址

前面几章一直把变量当作装数据的盒子，把数组当作排成一列的盒子。盒子里装着值，这是到目前为止看待数据的方式。指针换了一个角度：它关心的不是盒子里装了什么，而是盒子摆在内存的哪个位置。

## 每个盒子都有地址

内存可以想象成一长排连续编号的存储单元，每个单元都有一个编号，就像楼里每一间房都有门牌号。变量声明出来时，系统会在内存里划出一块空间给它，这块空间的起始编号就是这个变量的地址。值是盒子里装的东西，地址是盒子所在的位置，两者是两回事。

指针就是专门用来存地址的变量。普通变量存的是值——42、3.14、`'A'`，指针存的是"某个数据在内存里的门牌号"。

```cpp
int  x = 42;      // x 是一个 int，盒子里装着 42
int* p = &x;      // p 是一个指针，盒子里装着 x 的地址
```

类型写作 `int*`，意思是"指向 int 的指针"。`p` 本身也是一个盒子，只不过它装的内容是另一个盒子的门牌号。

```
内存示意图：

地址:    0x1000       0x1008
         ┌──────┐    ┌──────┐
内容:    │  42  │    │0x1000│
         └──────┘    └──────┘
变量名:     x            p
类型:      int         int*
```

`p` 里存着 `0x1000`，也就是 `x` 的地址，因此我们说 `p` 指向 `x`。

## 取地址与解引用

围绕指针只有两个基础操作，一个是拿到某个盒子的地址，一个是顺着地址找到那个盒子。取地址运算符 `&` 放在变量前面，得到它的地址；解引用运算符 `*` 放在指针前面，顺着指针里存的地址去访问那个盒子本身。

```cpp
int x = 42;
int* p = &x;       // & 取出 x 的地址，交给 p，于是 p 指向 x

*p = 100;          // * 顺着地址找到 x 这个盒子，往里写 100
// 此时 x == 100

int y = *p;        // * 顺着地址读出盒子里的值
// y == 100
```

`*p` 和 `x` 指的是同一个盒子，通过 `*p` 的读写等价于对 `x` 的读写。指针的全部威力都建立在这一点上：拿到一个盒子的地址，就能在别处操纵这个盒子。

## 指针的类型决定读多少字节

指针里存的只是一个地址，一个编号而已，编号本身并不说明从那里该读几个字节。这件事由指针的类型决定。`int*` 解引用时读 4 个字节并按整数解释，`double*` 解引用时读 8 个字节并按浮点解释。这正是数据类型那一章讲过的道理在指针上的延续——类型规定了盒子的大小和内容的读法。

```cpp
int*    pi;    // 指向 int 的指针，解引用读 4 字节
double* pd;    // 指向 double 的指针，解引用读 8 字节
float*  pf;    // 指向 float 的指针
void*   pv;    // 万能指针，可以存任何类型的地址，但因为不知道读几个字节，不能直接解引用
```

`void*` 是一个特例，它能存下任意类型的地址，但正因为丢掉了类型信息，编译器不知道解引用时该读多少、怎么解释，所以必须先转回具体类型才能使用。

## 空指针

指针也可能不指向任何有效的盒子，这种状态用 `nullptr` 表示。

```cpp
int* p = nullptr;  // p 不指向任何有效内存
```

对空指针解引用会顺着一个无效地址去访问内存，程序通常会当场崩溃。因此在解引用一个来路不明的指针之前，先确认它不为空是常见的自我保护。

```cpp
if (p != nullptr)
{
    *p = 42;  // 确认指向了有效盒子，才动手
}
```

## 通过指针访问成员

当指针指向的是一个结构体时，想访问它的成员，本该先解引用再取成员，写成 `(*pp).x`。这种写法括号多、读起来别扭，于是 C++ 提供了 `->` 作为简写。

```cpp
struct Point { float x, y; };

Point pt = {1.0f, 2.0f};
Point* pp = &pt;

pp->x = 10.0f;   // 等价于 (*pp).x = 10.0f
pp->y = 20.0f;   // 等价于 (*pp).y = 20.0f
```

`pp->x` 的含义就是"顺着 `pp` 找到那个结构体，取它的 `x` 成员"。

## 指针与数组本是一回事

数组那一章说过，数组是一排连续摆放的盒子。这排盒子的地址其实就是第一个盒子的地址，因此数组名在大多数场合会自动退化成指向首元素的指针。

```cpp
int arr[5] = {10, 20, 30, 40, 50};
int* p = arr;         // 数组名退化为指向首元素的指针
// 等价于 int* p = &arr[0];

p[0];  // 10
p[1];  // 20
p[2];  // 30
```

`p[i]` 本质上就是 `*(p + i)`：从首地址出发，往后跨过 `i` 个盒子，再解引用。指针加一并不是地址加一个字节，而是加一个元素的大小——`int*` 加一跨过 4 个字节，`double*` 加一跨过 8 个字节。类型再一次决定了步长。数组下标看似是一套独立语法，实际上只是指针运算的糖衣，这也解释了为什么数组传进函数后 `sizeof` 只能拿到指针的大小：函数收到的从来只是一个首地址。

## 常量与指针

`const` 和指针搭配时，位置不同含义也不同，关键看 `const` 限制的是"盒子里的数据"还是"指针本身指向谁"。

```cpp
const int* p1;        // 指向常量的指针：不能通过 p1 修改它指向的数据
int* const p2 = &x;   // 常量指针：p2 一旦指向某处就不能改指别处
const int* const p3 = &x;  // 数据和指向都不能改
```

区分的办法是看 `const` 挨着谁：挨着 `int` 就是数据不可改，挨着指针名就是指向不可改。

## 智能指针

裸指针最大的隐患是需要手动记得释放。用 `new` 在堆上申请的内存，必须配一次 `delete`，一旦忘记就造成内存泄漏。C++11 引入的智能指针把释放这件事交给对象的生命周期自动完成，离开作用域时自动清理。

`std::unique_ptr` 表示独占所有权，同一时刻只允许一个指针拥有这块内存。

```cpp
#include <memory>

std::unique_ptr<int> p1 = std::make_unique<int>(42);
// *p1 == 42

// std::unique_ptr<int> p2 = p1;         // 编译错误：不允许拷贝
std::unique_ptr<int> p2 = std::move(p1); // 移动：p2 接管，p1 变为 nullptr
// 离开作用域时自动 delete，不会泄漏
```

因为独占，`unique_ptr` 不能拷贝，只能通过 `std::move` 把所有权移交出去，这正是移动语义最典型的应用场景。`std::shared_ptr` 则表示共享所有权，它内部维护一个引用计数，允许多个指针指向同一块内存，最后一个销毁时才真正释放。

```cpp
std::shared_ptr<int> p1 = std::make_shared<int>(42);
std::shared_ptr<int> p2 = p1;   // 可以拷贝，引用计数变为 2
// 最后一个 shared_ptr 销毁时才释放内存
```

在 GSRL 中，当一个对象持有独占资源、不该被随意复制时，`unique_ptr` 能在编译期就挡住意外的拷贝，明确表达"我独占这个资源"的意图，并通过 `std::move` 显式转移所有权。

## 指针容易出错的地方

指针的危险都源于同一件事：它只是一个地址，地址所指向的盒子是否还有效，指针自己并不知道。

野指针指向一块已经失效的内存。函数里的局部变量在函数返回后就被销毁，此时返回它的地址，得到的就是一个指向已消失盒子的指针。

```cpp
int* getPointer()
{
    int x = 42;
    return &x;  // 返回局部变量的地址，x 随函数结束而销毁
}

int* p = getPointer();
*p = 100;  // 访问已释放的栈内存，未定义行为
```

重复释放是对同一块堆内存调用两次 `delete`，第二次释放的是一块已经不属于自己的内存，同样是未定义行为。

```cpp
int* p = new int(42);
delete p;
delete p;  // 重复释放，通常崩溃
```

内存泄漏则相反，是申请了却忘记释放，堆上的空间既无人使用又无法回收。

```cpp
void func()
{
    int* p = new int[1000];
    // 忘记 delete[] p，这 1000 个 int 永远丢失
}
```

## GSRL 中的指针

GSRL 里既用裸指针也用智能指针，选择取决于谁来负责这块内存的生命周期。行为树的子节点用裸指针数组存储，因为节点的生命周期由行为树统一管理，嵌入式环境又追求最小开销，不需要智能指针的额外负担。

```cpp
// alg_behavior_tree.hpp
BTNode* m_children[MaxChildren];  // 指针数组，存储子节点的地址
```

需要在堆上动态分配数组时，裸指针配对 `new`/`delete[]`，在构造时申请、析构时释放。

```cpp
// SimplePID 中
fp32* m_errorHistory;               // 指向堆上动态分配的数组
m_errorHistory = new fp32[historySize];  // 构造时分配
delete[] m_errorHistory;                 // 析构时释放
```

指针数组在使用前统一置零，也就是把每个指针初始化为 `nullptr`。

```cpp
// alg_behavior_tree.hpp
memset(static_cast<void*>(m_children), 0, sizeof(m_children));
```

## 指针与引用

引用是 C++ 里另一种间接访问的方式，它同样让你通过一个名字去操纵别处的数据，但比指针受约束得多。指针是一个独立的盒子，可以为空、可以改指别处；引用则更像给已有盒子起的别名，绑定之后终身不变，也不能为空。

| 特性 | 指针 | 引用 |
|------|------|------|
| 语法 | `int* p = &x;` | `int& r = x;` |
| 可否为空 | 可以是 `nullptr` | 不可以，必须绑定有效对象 |
| 可否重新绑定 | 可以 `p = &y;` | 不可以，绑定后终身不变 |
| 访问方式 | `*p` 或 `p->` | 直接用 `r`，像普通变量 |
| 使用场景 | 动态内存、可选参数、数组遍历 | 函数参数传递、避免拷贝 |

指针把"盒子的地址"这个概念显式地摆在面前，理解了它，动态内存、移动语义、乃至 GSRL 里大量的底层代码才有了根基。指针指向的数据究竟存在哪里、何时分配、何时释放，是下一章内存模型要讲清的事；而智能指针、移动语义这些真正把指针用好用稳的机制，会在 C++ 进阶篇里展开。
