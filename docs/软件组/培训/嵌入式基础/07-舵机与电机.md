# 舵机与电机控制

执行器是机器人把电信号转化为物理动作的部件，舵机和电机是其中最常见的两类。本章从它们的物理原理讲起，说明各自的控制方式，最后落到 GSRL 中 [CAN](./11-CAN通信原理.md) 总线电机的控制架构。

> 上一篇：[定时器与 PWM](./06-定时器与PWM.md)

## 1. 舵机

舵机要解决的问题是"转到某个角度并停在那里"，因此它本质上是一个闭环角度伺服系统，把角度控制所需的一切都集成在了一个壳子里。内部由直流电机提供动力，齿轮组把转速降下来、把扭矩放大，同时也放大了位置精度；电位器实时测量输出轴的角度；控制电路则不断比较目标位置（由输入的 PWM 信号给定）和电位器反馈的实际位置，驱动电机消除两者的误差。

```
┌─────────────────────────────────────────┐
│                舵机内部                   │
│                                         │
│  PWM 信号 ──→ ┌─────────┐               │
│              │ 控制电路 │               │
│              └────┬────┘               │
│                   │                    │
│              ┌────▼────┐               │
│              │ 直流电机 │──→ 齿轮组 ──→ 输出轴
│              └─────────┘               │
│                   │                    │
│              ┌────▼────┐               │
│              │ 电位器   │←── 反馈角度   │
│              │(位置反馈)│               │
│              └─────────┘               │
└─────────────────────────────────────────┘
```

正因为闭环控制在舵机内部就完成了，使用者不需要自己写 PID，只要通过 [PWM](./06-定时器与PWM.md) 信号的脉宽告诉它目标角度即可（PWM 的原理见上一章，PID 算法详见 GSRL Algorithm 层）。普通舵机的角度范围约 180°，上限由内部机械限位决定。还有一类总线舵机（如 Dynamixel），通过 UART/RS485 收发数字指令，除了控制角度，还能反馈位置、速度和电流。

选型时几个关键参数需要横向对照：

| 参数 | 典型值 | 含义 |
|------|--------|------|
| 工作电压 | 4.8V ~ 7.4V | 供电电压越高，扭矩和速度越大 |
| 堵转扭矩 | 15 ~ 40 kg·cm | 输出轴能承受的最大负载 |
| 响应速度 | 0.1 ~ 0.2 s/60° | 转动 60° 所需时间 |
| 死区 | 1~2 μs | 脉宽变化小于死区时舵机不响应 |
| 控制频率 | 50Hz (20ms) | 大部分舵机的标准控制频率 |

## 2. 直流有刷电机

直流有刷电机靠电刷和换向器让转子线圈中的电流方向不断切换，从而在永磁体磁场中获得持续同向的电磁力，保持旋转。换向器每转过一个角度就把电流反向一次，这样线圈受到的力始终朝着同一个方向。

```
简化模型：
      N          N          N
   ┌─────┐   ┌─────┐   ┌─────┐
   │ →→→ │   │ ↑↑↑ │   │ ←←← │   ← 转子线圈（电流方向随换向器翻转）
   └─────┘   └─────┘   └─────┘
      S          S          S

        换向器 (换角度后电流反向，维持同一方向的电磁力)
```

控制这类电机的转向和转速，常用 H 桥电路。它由 4 个开关管（MOSFET）组成，S1+S4 导通时电机正转，S2+S3 导通时反转，而 S1+S2 或 S3+S4 同时导通会造成电源短路，必须避免。用 PWM 信号控制开关管的导通时间，占空比从 0% 到 100% 变化，就实现了电压调速。

```
       VCC
        │
   ┌────┴────┐
   │ S1   S3 │      S1+S4 导通 → 正转
   │    M    │      S2+S3 导通 → 反转
   │ S2   S4 │      S1+S2 或 S3+S4 同时导通 → 短路（禁止！）
   └────┬────┘      占空比 0% ~ 100% → 调速
        │
       GND
```

## 3. 无刷直流电机（BLDC）

有刷电机的软肋在于电刷。电刷与换向器靠机械接触换向，是消耗品，高速大功率下磨损快、寿命短；接触时产生的火花还会带来电气噪声，干扰传感器和无线通信，在机器人上可能表现为 IMU 数据抖动或遥控信号丢包。无刷电机把永磁体放到转子上、线圈放到定子上，用电子换向取代机械换向，从根本上去掉了电刷。这样带来的收益是效率提升到约 85%~90%（有刷电机约 70%~75%），同等电池续航更久，而且功率密度更高，相同体积能输出更大扭矩，对空间紧张的机器人关节尤为重要。

```
无刷电机结构:
          ┌──────────┐
          │  定子线圈  │  ← 固定不动
    ┌─────┼──────────┼─────┐
    │     │   ┌──┐   │     │
    │     │   │永│   │     │  ← 转子旋转
    │     │   │磁│   │     │
    │     │   │体│   │     │
    │     │   └──┘   │     │
    └─────┴──────────┴─────┘
```

去掉了机械换向，就得靠电路决定何时给哪一相通电，这引出了两种换向方式。最简单的是六步换相（方波驱动）：依次给三相中的两相通电，每 60° 电角度切换一次，实现容易，但每次换相时电流方向突变，会产生转矩脉动，电机随之振动、发出噪音。比赛机器人上常用的高性能电机（大疆 M3508、达妙 DM4310 等）则采用 FOC（Field-Oriented Control，磁场定向控制）。

FOC 的核心是实时测量转子角度，用数学变换（Clarke + Park）把三相交流电流分解成转矩电流 Iq 和励磁电流 Id 两个分量，然后像控制直流电机那样分别控制它们。电流矢量连续平滑地旋转，产生的转矩也就连续平滑，没有换相的突变，也就没有振动。

```
┌──────────┐    ┌──────────┐    ┌──────────┐    ┌──────────┐
│ 目标扭矩 │ → │ PID 控制 │ → │ 坐标变换 │ → │ SVPWM   │ → 三相桥 → 电机
│ (电流)   │    │ (电流环) │    │ Clarke   │    │ (空间矢量)│
└──────────┘    └──────────┘    │ Park     │    └──────────┘
                                └──────────┘
                                     ↑
                               ┌──────────┐
                               │ 角度传感器│  ← 编码器/霍尔
                               └──────────┘
```

这种平滑性在云台（gimbal）应用中至关重要：六步换相的振动会让相机画面抖动，而 FOC 的平滑转矩是稳定拍摄的基础。这也是 M3508、DM4310 等比赛电机全部采用 FOC 的原因。值得强调的是，这些电机的驱动器（如大疆 C620 电调、达妙电机内置的驱动板）已经把电流环 FOC 做在了内部，使用者只需通过 CAN 总线发送目标电流值。换句话说，我们不需要自己实现 FOC，只需做好通信层和控制层。

无刷电机在机器人上普遍配 CAN 总线，而不是传统的 PWM 接口，原因在于反馈。PWM 控制是单向的：MCU 通过占空比告诉电机"转多快"，电机却无法回传任何信息，想要位置就得额外接编码器，想知道电流和温度还得再接传感器，一个电机至少 3 根线，六个电机就是 18 根。CAN 总线电机则是双向的，MCU 发送目标电流/位置/速度，电机同时回报当前角度、转速、转矩电流和温度。这种反馈正是闭环控制的前提——PID 控制器必须知道当前状态才能算出下一步输出。加之 CAN 只需 CAN_H 和 CAN_L 两根线就能菊花链串联数十个电机，布线大为简化：RoboMaster 机器人上 8 个关节电机用两根 CAN 线就能全部连上，换成 PWM 加编码器则要超过 30 根线。

## 4. GSRL 中的电机控制架构

GSRL 里几乎所有机器人关节都由 CAN 总线电机驱动，其控制是一个典型的分层闭环系统。控制层的 PID 控制器根据目标位置/速度与反馈的实际位置/速度算出目标电流；通信层通过 CAN 收发控制帧和反馈帧；物理层则是电机驱动板，由编码器、驱动板、三相桥和电机本体构成。

```
┌──────────────────────────────────────────────────┐
│                   控制层 (Control)                │
│                                                  │
│  目标位置/速度 ─→ PID 控制器 ─→ 目标电流/电压     │
│       ↑                              │           │
│       │                              │           │
│  实际位置/速度 (反馈)                  │           │
│       │                              │           │
├───────┼──────────────────────────────┼───────────┤
│       │         通信层 (CAN)          │           │
│       │                              │           │
│  CAN 反馈帧 ←──────────────→ CAN 控制帧          │
│       │                              │           │
├───────┼──────────────────────────────┼───────────┤
│       │        物理层 (电机驱动板)     │           │
│                                                  │
│  编码器 → 驱动板 → 三相桥 → BLDC 电机             │
└──────────────────────────────────────────────────┘
```

不同品牌电机的 CAN 协议各不相同，但闭环控制的逻辑是共通的。GSRL 用一个 `Motor` 基类（`dvc_motor.hpp`）把这些共有逻辑封装起来：它保存通信所需的 CAN 帧 ID 和收发缓冲，保存从反馈帧解析出的当前状态（角度、角速度、转矩电流、温度、在线与否），保存上层设定的目标状态，并持有一个 PID 控制器接口，对外提供位置、速度、电流、圈数等多种闭环控制方法。

```cpp
class Motor {
protected:
    // 通信
    uint32_t m_motorControlMessageID;    // CAN 控制帧 ID
    uint32_t m_motorFeedbackMessageID;   // CAN 反馈帧 ID
    uint8_t m_motorControlData[8];       // CAN 控制数据（发送）
    uint8_t m_motorFeedbackData[8];      // CAN 反馈数据（接收）

    // 当前状态（从 CAN 反馈中解析）
    fp32 m_currentAngle;                 // 当前角度 (rad)
    fp32 m_currentAngularVelocity;       // 当前角速度 (rad/s)
    int16_t m_currentTorqueCurrent;      // 当前转矩电流
    int8_t m_temperature;               // 温度
    bool m_isMotorConnected;            // 是否在线

    // 目标状态（由上层控制算法设定）
    fp32 m_targetAngle;
    fp32 m_targetAngularVelocity;
    int16_t m_targetTorqueCurrent;

    // 控制器
    Controller *m_controller;            // PID 控制器接口
    fp32 m_controllerOutput;            // 控制器输出

public:
    // 闭环控制（多种模式）
    fp32 angleClosedloopControl();              // 位置闭环
    fp32 angularVelocityClosedloopControl();    // 速度闭环
    int16_t torqueCurrentClosedloopControl();   // 电流闭环
    fp32 revolutionsClosedloopControl();        // 圈数闭环
    void openloopControl(fp32 controlValue);    // 开环控制
};
```

具体的电机型号通过继承 `Motor` 基类、各自适配对应的 CAN 协议来实现。目前支持的电机如下：

| 类名 | 电机型号 | 通信协议 |
|------|---------|---------|
| `MotorGM6020` | 大疆 GM6020 | 大疆 CAN 协议，一控多（电压控制） |
| `MotorM3508` | 大疆 M3508 | 大疆 CAN 协议（电流控制） |
| `MotorM2006` | 大疆 M2006 | 与 M3508 协议兼容 |
| `MotorDM4310` | 达妙 DMJ4310 | 达妙 MIT 模式（力矩控制） |
| `MotorDM2325` | 达妙 DM-S2325 | 与 DMJ4310 协议兼容 |
| `MotorDMmulti` | 达妙一控四固件 | 达妙力位混控模式 |
| `MotorLKMG` | 瓴控 MG 系列 | 瓴控协议 |

把这些串起来看一遍实际的控制流程。以 `tsk_test.cpp` 中的达妙电机为例，先声明 PID 控制器和电机对象，初始化 CAN，然后在一个 1ms 周期的循环里计算控制量并通过 CAN 发出，反馈则在中断服务程序里接收和解析。

```cpp
// 1. 声明 PID 控制器
SimplePID::PIDParam param = {
    10.0f,  // Kp
    0.0f,   // Ki
    0.0f,   // Kd
    100.0f, // outputLimit
    0.0f    // intergralLimit
};
SimplePID myPID(SimplePID::PID_POSITION, param);

// 2. 声明电机对象（ID=1, MasterID=3, PMAX=PI, VMAX=40, TMAX=15）
MotorDM4310 motor(1, 3, 3.1415926f, 40, 15, &myPID);

// 3. 在任务中初始化 CAN
CAN_Init(&hcan1, can1RxCallback);

// 4. 主循环：1ms 周期
while (1) {
    motor.openloopControl(sinf(2 * PI * 0.5f * xTaskGetTickCount() / 1000));
    // 将控制数据通过 CAN 发送给电机
    const uint8_t *data = motor.getMotorControlData();
    HAL_CAN_AddTxMessage(&hcan1, motor.getMotorControlHeader(), data, &send_mail_box);
    vTaskDelayUntil(&taskLastWakeTime, 1);
}

// 5. ISR 中接收反馈
void can1RxCallback(can_rx_message_t *pRxMsg) {
    motor.decodeCanRxMessageFromISR(pRxMsg);
}
```

数据在任务循环和中断之间的流转是这样的：

```
1ms 任务循环:
  motor.openloopControl()              ← 计算控制量
    → motor.getMotorControlHeader()    ← 获取 CAN 帧头
    → motor.getMotorControlData()      ← 获取 CAN 数据
    → HAL_CAN_AddTxMessage()           ← 通过 CAN1 发出

CAN 中断:
  CAN1_RX0_IRQHandler()
    → HAL_CAN_RxFifo0MsgPendingCallback()
      → can1RxCallback()
        → motor.decodeCanRxMessageFromISR()  ← 更新电机当前状态
```

## 5. 三类执行器的对比

舵机、有刷电机和 CAN 总线 BLDC 在控制接口、反馈能力和精度上差异明显，横向对照如下：

| 特性 | 舵机 | 直流有刷电机 | CAN 总线 BLDC |
|------|------|-------------|---------------|
| 控制接口 | PWM 脉宽 | PWM 占空比（H 桥） | CAN 总线数字指令 |
| 控制量 | 角度（位置） | 电压/转速 | 转矩电流（FOC） |
| 反馈 | 无（内部闭环） | 无（需编码器） | 角度/速度/电流/温度 |
| 精度 | ±1° | 取决于编码器 | 编码器精度（可达 0.01°） |
| 使用的控制器 | 舵机内置 | 需要外部 PID | 电机内置电流环 + 外置位置/速度 PID |
| GSRL 中的角色 | 较少使用 | 较少使用 | 主力执行器 |

GSRL 采用这种分层设计的价值在于解耦：`Motor` 基类定义位置/速度/电流闭环的接口，`SimplePID`、`CascadePID` 作为控制器实现，CAN Driver 负责数据传输。同一套控制算法因此可以无缝切换不同品牌的电机，需要换电机时只替换继承类即可。
