# 时钟树与总线架构

时钟是 MCU 的心脏，总线是 MCU 的血管。定时器周期、[PWM](./06-定时器与PWM.md) 频率、通信波特率这些"时间相关"的参数，归根到底都是从时钟树上算出来的。这一章从 STM32F407 的实际硬件出发，把时钟和总线讲透。

> 上一篇：[嵌入式系统概述与 HAL 库](./01-嵌入式系统概述与HAL库.md)

---

## 1. 为什么需要时钟树

MCU 内部有数十个外设，它们对工作频率的要求各不相同：CPU 内核希望跑得越快越好（168MHz），USB 要求恰好的 48MHz，[定时器](./06-定时器与PWM.md)需要灵活的频率来产生精确的 [PWM](./06-定时器与PWM.md) 和定时周期，[UART](./08-UART通信原理.md) 要根据波特率算出分频系数，而低功耗外设则希望频率越低越省电。

如果整颗芯片只有一个固定频率，这些需求根本没法同时满足：让 CPU 跑 168MHz，USB 就拿不到它需要的 48MHz，低速外设也在白白耗电；反过来统一压到最低频率，CPU 性能又大打折扣。时钟树（Clock Tree）就是为解决这个矛盾而生的——它从一个或多个时钟源出发，通过分频和倍频，为每个外设送去恰好合适的频率，本质上是在性能、功耗和功能正确性之间做精确的分配。

这套机制可以类比城市供水：水库是时钟源，自来水厂负责倍频和"净化"（PLL），主管道是 AHB 总线，再经过各个减压阀（APB 预分频器）分出不同压力的管道供给不同外设。

```
水库 (时钟源)  ──→  自来水厂 (PLL 倍频/净化)  ──→  主管道 (AHB 总线)
                                                    │
                            ┌───────────────────────┼───────────────────────┐
                            │                       │                       │
                        减压阀 (APB1 预分频器)   直接供 (AHB)          减压阀 (APB2 预分频器)
                            │                       │                       │
                        低压管道                   高压管道                中压管道
                      (42MHz max)               (168MHz max)            (84MHz max)
                            │                       │                       │
                      TIM2~TIM7               GPIO, DMA,               TIM1, TIM8
                      USART2~3                ETH, USB_OTG             USART1, USART6
                      I2C1~I2C3               RCC, Flash               SPI1, ADC
                      SPI2~SPI3                                       SYSCFG
```

## 2. 时钟源——一切时间的起点

时钟树的一切频率都源自时钟源。STM32F407 有四个独立的时钟源，精度和用途各不相同：

| 时钟源 | 类型 | 频率 | 精度 | 用途 |
|--------|------|------|------|------|
| **HSI** | 内部 RC 振荡器 | 16 MHz | 低（±1%，温漂大） | 启动时临时使用、故障后备 |
| **HSE** | 外部晶振 | 8 MHz（GSRL 用 8MHz） | 高（±10ppm） | ★ 正常运行的主时钟源 |
| **LSI** | 内部低速 RC | 32 kHz | 低 | 独立看门狗 (IWDG) |
| **LSE** | 外部低速晶振 | 32.768 kHz | 高 | RTC 实时时钟 |

GSRL 工程选用 8MHz 的外部晶振（HSE）作为主时钟源，经 PLL 倍频得到 168MHz 的系统时钟。

```
GSRL 工程的时钟源选择:
  HSE = 8MHz 外部晶振  →  PLL 倍频  →  SYSCLK = 168MHz

为什么是 8MHz？
  - 8MHz 是 STM32 最常见的晶振频率
  - 经过 PLL 倍频可以精确得到 168MHz (8 / 8 × 336 / 2 = 168)
  - 同时可以精确分出 48MHz 给 USB (8 / 8 × 336 / 7 = 48)
```

这里值得说明为什么必须用外部晶振而不是更省事的内部振荡器（HSI）。关键在精度：HSI 的误差高达 ±1%，会直接导致 UART 波特率偏差和 [CAN](./11-CAN通信原理.md) 位时序偏移，一旦超过协议的容忍上限，通信就彻底失效。HSE 晶振的 ±10ppm 精度（误差仅十万分之一）才是可靠通信的物理基础。HSI 只在芯片刚上电启动、以及 HSE 出故障时作为应急备选。

## 3. PLL——频率的乘法器

既然要跑 168MHz，为什么不直接用一个 168MHz 的晶振？因为晶振频率越高，制造难度和成本就越大，8MHz 是稳定性与经济性兼顾的选择。要把这个低频晶振信号提升到 168MHz，就得靠 PLL 倍频。PLL 还有一个简单倍频电路做不到的本事：从一个晶振同时产生多路不同频率的输出，比如一路 168MHz 给 CPU、另一路 48MHz 给 USB。

PLL（Phase-Locked Loop，锁相环）是模拟电路里的"频率乘法器"。它内部由鉴相器、环路滤波器和压控振荡器构成一个反馈环：压控振荡器（VCO）产生高频信号，经 N 分频后与输入信号比较相位，不断调整 VCO，直到分频后的频率与输入频率一致。环路锁定后就有 `f_out / N = f_in`，即 `f_out = f_in × N`。

```
                    ┌──────────┐
    输入频率 f_in   │ 鉴相器    │    ┌──────────┐    ┌──────────┐    输出频率 f_out
   ───────────────→│ (PFD)    │───→│ 环路滤波器 │───→│ 压控振荡器 │──→ f_out = f_in × N/M
                   │          │    │  (LPF)    │    │  (VCO)   │
              ┌───→│          │    └──────────┘    └────┬─────┘
              │    └──────────┘                        │
              │                                        │
              │          ┌──────────┐                  │
              └──────────│ N 分频器  │←─────────────────┘
                         │  (÷N)    │
                         └──────────┘

原理: VCO 产生高频信号 → ÷N 分频后与输入信号比较
     → 调整 VCO 使分频后频率 = 输入频率
     → 锁定后: f_out / N = f_in → f_out = f_in × N
```

在 STM32F4 上，PLL 是一条带多个分频/倍频系数的通路：HSE 先经 ÷M 降到很低的输入频率，再经 ×N 倍频到 VCO 频率，最后分出 ÷P 和 ÷Q 两路输出，分别供 CPU 和 USB 使用。

```
HSE (8MHz)
    │
    ├─ ÷M (PLLM=8)  →  8MHz / 8 = 1 MHz         ← PLL 输入频率必须 ≤ 2MHz
    │
    ├─ ×N (PLLN=336) →  1MHz × 336 = 336MHz       ← VCO 输出 (100~432MHz 合法)
    │
    ├─ ÷P (PLLP=2)  →  336MHz / 2 = 168MHz       ← SYSCLK (CPU 时钟)
    │
    └─ ÷Q (PLLQ=7)  →  336MHz / 7 = 48MHz        ← USB OTG / RNG (精确 48MHz)
```

这里的 ÷M 不是可有可无的一步。PLL 内部鉴相器（PFD）只有一段有限的线性工作范围，输入频率过高时它来不及正确比较相位，会导致环路失锁、输出频率剧烈抖动甚至完全错误。把 8MHz 先除到 1~2MHz，正是为了让鉴相器工作在稳定可靠的区间，所以 PLL 输入频率必须限制在约 2MHz 以内。

这套配置对应 GSRL `main.c` 中的 `SystemClock_Config()`：

```c
void SystemClock_Config(void)
{
    RCC_OscInitTypeDef RCC_OscInitStruct = {0};
    RCC_ClkInitTypeDef RCC_ClkInitStruct = {0};

    // ① 使能 PWR 时钟，配置调压器为最高性能模式
    __HAL_RCC_PWR_CLK_ENABLE();
    __HAL_PWR_VOLTAGESCALING_CONFIG(PWR_REGULATOR_VOLTAGE_SCALE1);

    // ② 配置时钟源: 使用 HSE (8MHz 外部晶振)
    RCC_OscInitStruct.OscillatorType = RCC_OSCILLATORTYPE_HSE;
    RCC_OscInitStruct.HSEState = RCC_HSE_ON;

    // ③ 配置 PLL: M=8, N=336, P=2, Q=7
    RCC_OscInitStruct.PLL.PLLState = RCC_PLL_ON;
    RCC_OscInitStruct.PLL.PLLSource = RCC_PLLSOURCE_HSE;
    RCC_OscInitStruct.PLL.PLLM = 8;
    RCC_OscInitStruct.PLL.PLLN = 336;
    RCC_OscInitStruct.PLL.PLLP = RCC_PLLP_DIV2;
    RCC_OscInitStruct.PLL.PLLQ = 7;
    HAL_RCC_OscConfig(&RCC_OscInitStruct);

    // ④ 配置系统时钟: SYSCLK = PLLCLK = 168MHz
    //    HCLK = SYSCLK / 1 = 168MHz    (AHB 总线)
    //    PCLK1 = HCLK / 4 = 42MHz      (APB1 总线)
    //    PCLK2 = HCLK / 2 = 84MHz      (APB2 总线)
    RCC_ClkInitStruct.ClockType = RCC_CLOCKTYPE_HCLK | RCC_CLOCKTYPE_SYSCLK
                                | RCC_CLOCKTYPE_PCLK1 | RCC_CLOCKTYPE_PCLK2;
    RCC_ClkInitStruct.SYSCLKSource = RCC_SYSCLKSOURCE_PLLCLK;
    RCC_ClkInitStruct.AHBCLKDivider = RCC_SYSCLK_DIV1;     // ÷1
    RCC_ClkInitStruct.APB1CLKDivider = RCC_HCLK_DIV4;      // ÷4
    RCC_ClkInitStruct.APB2CLKDivider = RCC_HCLK_DIV2;      // ÷2
    HAL_RCC_ClockConfig(&RCC_ClkInitStruct, FLASH_LATENCY_5);
}
```

从晶振到各外设的完整通路可以用一张图串起来。PLL 分出 SYSCLK 后，先到 AHB 总线（HCLK），再经 APB1、APB2 两个预分频器分给各自的外设，SysTick、RTC、看门狗则另有时钟来源：

```
                          HSE (8MHz 外部晶振)
                              │
                              │ ÷M (PLLM=8)
                              ▼
              ┌─────  PLL 输入 = 1MHz  ─────┐
              │                                  │
              │ ×N (PLLN=336)                    │
              ▼                                  │
         VCO = 336MHz                            │
              │                                  │
     ┌────────┼────────┬──────────┐              │
     │ ÷P=2  │ ÷Q=7   │ 其他PLL输出│              │
     ▼       ▼        ▼           ▼              │
  PLLCLK  PLL48CK  PLLI2SCLK  PLLSAICLK          │

     │                                           │
     ├──→ SYSCLK (系统时钟) = 168MHz              │

     │       │       │                           │
```

## 4. 总线架构——数据的高速公路

时钟解决了"跑多快"，总线解决的是"数据怎么走"。STM32F4 用一套多层 AHB 总线矩阵把 CPU、内存和外设连起来，Cortex-M4、DMA、USB 这些能主动发起传输的是总线主设备，Flash、SRAM、FSMC 是被访问的存储器：

```
┌─────────────────────────────────────────────────────────────┐
│                     AHB 总线矩阵                             │
│                                                             │
│  ┌──────┐  ┌──────┐  ┌──────┐  ┌──────┐                   │
│  │Cortex│  │ DMA1 │  │ DMA2 │  │ USB  │  ← 总线主设备       │
│  │ -M4  │  │      │  │      │  │ OTG  │   (可以发起传输)     │
│  └──┬───┘  └──┬───┘  └──┬───┘  └──┬───┘                   │
│     │         │         │         │                         │
│     └─────────┴─────────┴─────────┘                         │
│                    │                                        │
│     ┌──────────────┼──────────────┐                         │
│     ▼              ▼              ▼                         │
│  ┌──────┐    ┌──────────┐   ┌──────────┐                   │
│  │Flash │    │  SRAM    │   │  FSMC    │  ← 存储器          │
│  │512KB │    │  192KB   │   │ (外部)   │                    │
│  └──────┘    └──────────┘   └──────────┘                   │
│     │                                                      │
│     ├── AHB1 ──→ GPIO, RCC, DMA, CRC, ETH, USB_OTG         │
│     ├── AHB2 ──→ DCMI, 摄像头                              │
│     ├── AHB3 ──→ FSMC                                      │
│     │                                                      │
│     ├── APB1 ──→ TIM2~7,12~14, USART2~3, I2C1~3, SPI2~3,  │
│     │            CAN1~2, RTC, DAC, PWR, WWDG               │
│     │                                                      │
│     └── APB2 ──→ TIM1,8~11, USART1,6, SPI1, ADC, SYSCFG,  │
│                  EXTI, SDIO                                 │
└─────────────────────────────────────────────────────────────┘
```

外设分挂在 APB1 和 APB2 两条总线上，这不是随意划分，而是按速度需求分级：APB2（84MHz）挂 SPI1、USART1、ADC 等需要较高吞吐率的外设，APB1（42MHz）承载 CAN、I2C、USART2~3 等对速度要求较低的外设。这样分级有两点好处，一是低速总线功耗更低，且更长的信号路径容限让芯片物理布局更灵活；二是把外设分散到两条总线，减少了多主机同时访问时的总线仲裁冲突。

各条总线挂了哪些外设、跑什么频率，可以对照速查：

| 总线 | 时钟频率 (GSRL) | 挂载的外设 | 影响 |
|------|----------------|-----------|------|
| **AHB** | 168MHz (HCLK) | [GPIO](./03-GPIO与高低电平.md), DMA, 内核 | GPIO 翻转速度、DMA 传输速率 |
| **APB1** | 42MHz (PCLK1) | TIM2~7, CAN, [I2C](./10-I2C通信原理.md), SPI2~3, USART2~3 | ★ 定时器时钟实际 84MHz (×2) |
| **APB2** | 84MHz (PCLK2) | TIM1, TIM8, SPI1, USART1,6, ADC | ★ 定时器时钟实际 168MHz (×2) |

表里两个带 ★ 的注脚指向 STM32 一个最容易被忽略的细节：APB 上定时器的时钟频率并不等于 PCLK。规则是——当 APB 预分频器不等于 1 时，挂在这条 APB 上的定时器时钟等于 PCLK 的两倍。

```
规则: 当 APB 预分频器 ≠ 1 时，挂在该 APB 上的定时器时钟 = PCLK × 2

GSRL 实例:
  APB1 预分频 = ÷4  (≠1)
    → PCLK1 = 168 / 4 = 42MHz
    → APB1 Timer Clock = 42 × 2 = 84MHz   ← TIM2~TIM7 实际运行的频率!

  APB2 预分频 = ÷2  (≠1)
    → PCLK2 = 168 / 2 = 84MHz
    → APB2 Timer Clock = 84 × 2 = 168MHz  ← TIM1, TIM8 实际运行的频率!
```

ST 这样设计是有道理的。APB 总线本身跑不了太高频率，因为寄存器访问涉及地址译码、读写时序和等待状态等复杂逻辑，频率一高这些操作的时序窗口就会被压缩到出问题；而定时器的计数器只是一条简单的自增电路，几乎没有组合逻辑延迟，天然能承受更高频率。与其为了给定时器提速而让整条 APB 总线冒险超频，不如单独给计数器 ×2，既让定时器获得更精细的时间分辨率，又不影响总线上其他外设。这是典型的局部优化优于全局升频的工程取舍。

## 5. 时钟如何决定一切"时间参数"

说时钟树是一切时间参数的源头，不是一句口号。定时器周期、PWM 频率、UART 波特率、CAN 位时序、SPI 时钟，全都是拿某条总线的时钟频率经过分频算出来的。下面逐一展开。

### 5.1 定时器周期与 PWM 频率

定时器的核心是一组分频与计数公式：

```
定时器计数频率  = TIM_CLK / (PSC + 1)
定时器溢出频率  = 定时器计数频率 / (ARR + 1)
PWM 频率        = 定时器溢出频率
PWM 周期        = 1 / PWM 频率
PWM 分辨率      = ARR + 1  (有效占空比档位)
```

**实例 1：产生 50Hz 舵机 PWM（周期 20ms）**

```
条件: 使用 TIM4 (挂 APB1, TIM_CLK = 84MHz)
目标: PWM 频率 = 50Hz, 分辨率 ≥ 20000 档 (每档 1μs)

方案:
  PSC = 84MHz / (50Hz × 20000) - 1 = 84,000,000 / 1,000,000 - 1 = 83
  ARR = 20000 - 1 = 19999

验证:
  计数频率 = 84MHz / (83 + 1) = 1MHz  (每 1μs 计一次数)
  PWM 周期 = (19999 + 1) / 1MHz = 20ms ✓
  PWM 频率 = 1MHz / (19999 + 1) = 50Hz ✓
  分辨率   = 20000 档 (可精确到 1μs) ✓

控制舵机到 90° (脉宽 1.5ms):
  CCR = 1.5ms / 1μs = 1500
```

**实例 2：产生 20kHz 电机 PWM（驱动 H 桥）**

```
条件: 使用 TIM1 (挂 APB2, TIM_CLK = 168MHz)
目标: PWM 频率 = 20kHz, 分辨率 ≥ 1000 档

方案:
  PSC = 0  (不分频，直接使用 168MHz)
  ARR = 168MHz / 20kHz - 1 = 8399

验证:
  PWM 频率 = 168MHz / (0 + 1) / (8399 + 1) = 20,000Hz ✓
  分辨率   = 8400 档 ✓

占空比 50%:
  CCR = 8400 / 2 = 4200
```

### 5.2 UART 波特率

UART 的波特率由 USART 外设的输入时钟经过 16 倍过采样分频得到，分频值 USARTDIV 是个小数，整数部分放在 BRR 寄存器的 DIV_Mantissa，小数部分放在 DIV_Fraction（4 bit，精度 1/16）：

```
USART 时钟源      = PCLK (由所在 APB 决定) 或 SYSCLK
过采样率          = 16× (标准) 或 8× (高速)
波特率            = USART_CLK / (16 × USARTDIV)

USARTDIV 是一个小数分频值，整数部分在 BRR 寄存器的 DIV_Mantissa，
小数部分在 DIV_Fraction (4 bit, 精度 1/16)
```

**实例：USART1 (APB2, 84MHz) 产生 115200 bps**

```
USARTDIV = 84,000,000 / (16 × 115200) = 45.5729...

整数部分 = 45  (DIV_Mantissa)
小数部分 = 0.5729 × 16 = 9.166 ≈ 9  (DIV_Fraction)

实际波特率 = 84,000,000 / (16 × (45 + 9/16))
           = 84,000,000 / (16 × 45.5625)
           = 84,000,000 / 729
           = 115,226 bps

误差 = (115,226 - 115,200) / 115,200 = 0.023%   ← 完全可接受 (< 2%)
```

这也解释了晶振频率为什么讲究：不是任意晶振都能精确产生任意波特率。8MHz HSE 配合 PLL 得到 168MHz 系统时钟后，APB2 的 84MHz 能精确产生绝大多数常用波特率，这正是 STM32 推荐用 8MHz 晶振的一个原因。

### 5.3 CAN 位时序

[CAN](./11-CAN通信原理.md) 总线的位速率（Nominal Bit Rate）由 CAN 外设时钟（APB1 = 42MHz）分频得到。它把一个位划分成若干时间量子（Tq），一位由同步段、BS1 和 BS2 三段组成：

```
Tq (时间量子) = Prescaler / CAN_CLK        (Prescaler = 寄存器 BRP + 1)
一位的 Tq 总数 = SYNC_SEG(1) + BS1 + BS2
位速率        = 1 / (Tq 总数 × Tq)
             = CAN_CLK / (Prescaler × (1 + BS1 + BS2))

CAN_CLK = APB1_CLK = 42MHz  (CAN1 和 CAN2 都挂在 APB1 上)
```

要得到精确速率，`Prescaler × (1 + BS1 + BS2)` 必须整除 `CAN_CLK / 波特率`。

**实例：产生 RoboMaster 标准的 1Mbps CAN 波特率**

目标是让 `Prescaler × (1 + BS1 + BS2) = 42MHz / 1Mbps = 42`。同时采样点（Sample Point）应落在 75%~87.5% 区间，采样点 = `(1 + BS1) / (1 + BS1 + BS2)`。

```
选择: Prescaler = 3, BS1 = 11, BS2 = 2, SJW = 1
  Tq 总数 = 1 + 11 + 2 = 14
  验证: 42MHz / (3 × 14) = 42 / 42 = 1Mbps ✓
  采样点 = (1 + 11) / 14 ≈ 85.7%  ← 落在推荐区间 ✓
```

对应的 CubeMX/HAL 配置：

```c
hcan1.Init.Prescaler = 3;
hcan1.Init.SyncJumpWidth = CAN_SJW_1TQ;
hcan1.Init.TimeSeg1 = CAN_BS1_11TQ;   // BS1 = 11 Tq
hcan1.Init.TimeSeg2 = CAN_BS2_2TQ;    // BS2 = 2 Tq
// 位速率 = 42MHz / (3 × (1 + 11 + 2)) = 1Mbps
```

满足 `Prescaler × (1 + BS1 + BS2) = 42` 的组合不止一种（比如 Prescaler=6、BS1=4、BS2=2 也得到 1Mbps，但采样点只有 71%）。选择时优先保证采样点落在 75%~87.5%，因为它决定了总线对时钟偏差的容忍度。

### 5.4 SPI 时钟频率

SPI 的时钟最简单，就是 APB 时钟按 2 的整数次幂分频：

```
SPI_SCLK = APB_CLK / (2 ^ BR[2:0])

STM32F4 SPI 的预分频器:
  BR = 0: ÷2    → SPI1 (APB2=84MHz)  → 42MHz max
  BR = 1: ÷4    → 21MHz
  BR = 2: ÷8    → 10.5MHz
  BR = 3: ÷16   → 5.25MHz
  BR = 4: ÷32   → 2.625MHz
  BR = 5: ÷64   → 1.3125MHz
  BR = 6: ÷128  → 656kHz
  BR = 7: ÷256  → 328kHz
```

**实例：BMI088 [SPI](./09-SPI通信原理.md) 通信**

BMI088 的 SPI 最高支持 10MHz。GSRL 使用 SPI1（APB2 = 84MHz），选 BR=3（÷16）：

```
SPI1_SCLK = 84MHz / 16 = 5.25MHz  ← 在 BMI088 的 10MHz 限制内
```

## 6. 牵一发而动全身——修改时钟的影响

因为所有时间参数都从时钟树派生，一旦改动时钟配置（比如把晶振换成 12MHz），下面这些参数就全部需要重新计算，漏掉任何一处都可能导致外设工作异常：

| 受影响的外设 | 需要重新计算的参数 |
|-------------|-------------------|
| 定时器 | PSC、ARR → PWM 频率、舵机脉宽、编码器采样率 |
| UART | BRR → 波特率 |
| CAN | Prescaler、BS1、BS2 → 位速率 |
| SPI | BR → SCLK 频率 |
| I2C | Timing 寄存器 → 通信速率 |
| SysTick | 系统 tick 中断频率 → FreeRTOS 时基 |
| ADC | 采样时间 → 有效采样率 |
| USB | 48MHz 必须精确 → 否则 USB 无法枚举 |

一句话，所有"时间"都从时钟树上长出来。

## 7. 时钟安全机制

在机器人、无人机这类强振动环境里，外部晶振可能因物理冲击而损坏——焊点开裂、晶片破碎并不罕见。一旦 HSE 停振，CPU 就失去了时钟源而完全停摆，这在运动控制场景中意味着灾难性的失控。STM32 内置的时钟安全系统（CSS, Clock Security System）就是为应对这一风险而设，它会自动检测 HSE 是否失效，并在失效时切换到备用时钟，为系统争取自救时间。

```
如果 HSE 失效 (晶振损坏/起振失败):
  → CSS 自动切换到 HSI (16MHz)
  → 产生 NMI 中断 (不可屏蔽中断)
  → 用户可在 NMI_Handler 中做紧急处理

在 GSRL 的 stm32f4xx_it.c 中:
  void NMI_Handler(void)
  {
      while (1) {}  // 时钟失效 → 死循环，等待看门狗复位
  }
```

除此之外，CubeMX 生成的 `SystemClock_Config()` 会检查 `HAL_RCC_OscConfig()` 和 `HAL_RCC_ClockConfig()` 的返回值，配置失败就调用 `Error_Handler()`。

## 9. 小结

| 要点 | 说明 |
|------|------|
| 时钟树 | 从一个晶振出发，经 PLL 倍频/分频，为各外设提供不同频率 |
| PLL | 频率乘法器，核心公式 f_out = f_in × N / M |
| HSE | 8MHz 外部晶振，GSRL 的主时钟源 |
| APB 定时器 ×2 | 当 APB 分频器 ≠ 1 时，定时器时钟 = PCLK × 2 |
| 定时器公式 | 计数频率 = TIM_CLK / (PSC+1)，溢出频率 = 计数频率 / (ARR+1) |
| 所有时间参数 | 都从时钟树派生，改晶振需重算所有 PSC/ARR/BRR/BRP |
| 总线架构 | CPU ↔ AHB 矩阵 ↔ APB1/APB2，不同外设挂不同总线 |

GSRL 的 `main.c` 中 `SystemClock_Config()` 定义了整个工程的时钟基准，`CubeMX_BSP/Inc/main.h` 中的 `HAL_GetTick()` 依赖 SysTick（来自 SYSCLK 的 ÷8 分频）。定时器 PSC/ARR、CAN 的 Prescaler、UART 的 BRR、SPI 的 BR，这些参数的选取都直接依赖本章的时钟公式。后续阅读定时器 PWM 和通信协议章节时，可以随时回来查阅速查卡。
