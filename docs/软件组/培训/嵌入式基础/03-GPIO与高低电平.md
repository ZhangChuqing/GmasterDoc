# GPIO 与高低电平

GPIO 是 MCU 与外部世界交互最基本的方式。这一章从物理层的高低电平讲起，说明 GPIO 的几种工作模式各自解决什么问题，以及在 HAL 库中如何操作。

> 上一篇：[时钟树与总线架构](./02-时钟树与总线架构.md)

---

## 1. 高低电平与引脚的本质

在数字电路里，一切信息最终都归结为电压。电压接近供电电压（STM32 通常是 3.3V）就是高电平，逻辑上记为 `1`；电压接近 0V（GND）就是低电平，记为 `0`。实际判断并不是严格卡在 3.3V 或 0V，而是有一个区间：STM32 的输入阈值大约在 1.0V~2.0V 之间，落在中间的电压属于"不确定区"，这一点后面讲浮空输入时会反复用到。

```
电压
 │  3.3V ────────────────  高电平 (High / 1 / SET)
 │
 │  0V   ────────────────  低电平 (Low  / 0 / RESET)
 └────────────────────────────→ 时间
```

那么引脚是怎么产生这两种电平的？每个 GPIO 引脚内部有一个推挽电路，由两个 MOSFET 开关组成，一个连到 VDD、一个连到 GND。让上管（PMOS）导通、下管（NMOS）截止，引脚就被接到 3.3V 输出高电平；反过来上管截止、下管导通，引脚被接到 0V 输出低电平。

```
输出高电平:              输出低电平:
    VDD(3.3V)               VDD(3.3V)
       │                        │
    ┌──┴──┐                 ┌──┴──┐
    │ PMOS│ ON              │ PMOS│ OFF
    └──┬──┘                 └──┬──┘
       │                        │
       ├──────→ 引脚 3.3V       ├──────→ 引脚 0V
       │                        │
    ┌──┴──┐                 ┌──┴──┐
    │ NMOS│ OFF             │ NMOS│ ON
    └──┬──┘                 └──┬──┘
       │                        │
      GND                      GND
```

## 2. GPIO 的工作模式

GPIO 有输出和输入两个方向，每个方向又各有两种常用模式。它们的差别可以先看下表，后面逐一说明各自解决什么问题：

| 模式 | 方向 | 用途 | 内部上/下拉 |
|------|------|------|-------------|
| **推挽输出** (Push-Pull) | 输出 | 驱动 LED、控制信号 | 不需要 |
| **开漏输出** (Open-Drain) | 输出 | I2C 总线、电平转换 | 需外部上拉 |
| **浮空输入** (Floating Input) | 输入 | 读取按键（需外部上/下拉） | 无，引脚悬空时电平不确定 |
| **上拉/下拉输入** (Pull-Up/Down) | 输入 | 读取按键、外部中断触发 | 内置电阻上/下拉 |

### 2.1 推挽输出

推挽输出是日常最常用的输出模式。它的特点是两个 MOSFET 一推一拉，无论输出高还是低，引脚都有一条低阻抗通路连到 VDD 或 GND，因此信号切换速度快，驱动能力也强（典型值 8~25mA），直接驱动 LED 这类负载很合适。

```c
// 推挽输出：直接点亮 LED
HAL_GPIO_WritePin(LED_GPIO_Port, LED_Pin, GPIO_PIN_SET);   // LED 亮
HAL_GPIO_WritePin(LED_GPIO_Port, LED_Pin, GPIO_PIN_RESET); // LED 灭
```

但推挽输出有一个致命缺陷，正是它决定了什么场合不能用它。设想两个推挽输出引脚直接连在一起，一个输出高（PMOS 导通到 VDD）、另一个输出低（NMOS 导通到 GND），VDD 和 GND 之间就形成了一条近乎零电阻的通路：

```
致命短路路径：
    VDD
     │
  ┌──┴──┐  ON  ← GPIO_A 输出高
  └──┬──┘
     │
     ├────────── 短路！大电流直接流入
     │
  ┌──┴──┐  ON  ← GPIO_B 输出低
  └──┬──┘
     │
    GND
```

这一瞬间会有数百毫安甚至更大的电流流过两个引脚，足以烧毁 MCU 的 IO 驱动管。所以在多个设备共享的信号线上，只要有任意两个设备用推挽输出且状态不同，就会短路——这正是总线上必须改用开漏输出的根本原因。

### 2.2 开漏输出

开漏输出去掉了上管，只保留下管（NMOS），因此它只能主动把引脚拉低，没法主动输出高电平。要得到高电平，得靠外部上拉电阻把引脚拉到 VDD。

```
开漏输出结构:
    VDD ──[上拉电阻]──┬── 引脚
                      │
                  ┌───┴───┐
                  │ NMOS   │  ← 只有一个下拉管
                  └───┬───┘
                      │
                     GND

NMOS 导通 → 引脚被拉到 GND → 低电平
NMOS 截止 → 上拉电阻把引脚拉到 VDD → 高电平
```

正因为没有上管，多个开漏输出可以直接并接在同一根线上而不会短路，这是它相对推挽最大的价值。它的工作方式是"线与"（Wired-AND）：任意一个设备把线拉低，整条线就是低；只有所有设备都释放，上拉电阻才能把线拉回高。I2C、One-Wire 这类总线能支持多设备共享，靠的就是这个原理。开漏还天生支持电平转换——上拉电阻接到 5V，引脚就输出 5V 逻辑；接到 3.3V，就输出 3.3V 逻辑，比专用电平转换芯片灵活得多，成本几乎为零。

代价也有三点。一是上升沿慢：输出高电平时全靠上拉电阻给引脚和走线的寄生电容充电，RC 时间常数决定了从低到高的速度，上拉电阻越大越省电但上升沿越慢，I2C 标准模式（100kHz）没问题，但要跑到快速模式（400kHz 甚至 1MHz）就得减小上拉电阻，在速度和功耗间权衡。二是高电平驱动能力弱：输出高时电流只能从上拉电阻来，通常仅几百微安，远不如推挽的数十毫安，所以开漏的高电平只能"传递信号"，不能"驱动负载"。三是低电平时持续耗电：输出低时 VDD → 上拉电阻 → NMOS → GND 这条通路一直有电流。

推挽和开漏各有取舍，也就解释了不同通信协议为什么选择不同的输出方式：

| 协议 | 输出方式 | 原因 |
|------|----------|------|
| SPI | 推挽输出 | 点对点通信，只有一主一从，不存在冲突风险；需要高速（MHz 级别），推挽的强驱动能力正合适 |
| I2C | 开漏输出 | 多设备共享一条总线，必须避免短路；速度要求相对低（100kHz~1MHz），开漏的上升沿问题在可接受范围内 |
| UART | 推挽输出 | 点对点，不需要多主，推挽最简单可靠 |

开漏输出最典型的两个应用，一是 [I2C](./10-I2C通信原理.md) 总线，多设备共享同一根线必须靠开漏避免冲突；二是电平转换，上拉到 5V 即可让 3.3V 的 MCU 输出 5V 信号去驱动 5V 设备。

### 2.3 浮空输入的隐患

初学者常有一个误区：引脚什么都不接，读到的不就是低电平吗？并非如此。CMOS 输入端的输入阻抗极高（通常在兆欧级别），几乎不从外部汲取电流，这意味着引脚对外界电场极度敏感，像一根天线，电磁干扰、旁边信号线的切换、甚至手指靠近，都能在它上面感应出微小的电压变化，于是悬空引脚的电平是不确定的。

后果比想象的更严重。第一是随机跳变：悬空引脚的电压在高低阈值之间飘忽，读到的值一会儿是 0 一会儿是 1，如果这个引脚接的是外部中断线，就会产生大量虚假中断，白白打断 CPU。第二是振荡与漏电：当引脚电压停在 CMOS 输入缓冲器的中间区域时，内部的 PMOS 和 NMOS 可能同时部分导通，形成从 VDD 到 GND 的漏电流（crowbar current），单个引脚不大，但多个悬空引脚累加起来会明显抬高 MCU 的静态功耗。第三是按键翻车的经典案例：把按键一端接引脚、另一端接 GND，却没配上拉电阻，按下时引脚被拉到 GND 读到 0 没问题，可松开后引脚悬空，读到 0 还是 1 全凭运气，按键就会"鬼触"。

解决办法就是上下拉电阻，用一条确定的电阻路径把悬空的引脚"锚定"在某个电平上。

### 2.4 上拉/下拉输入

STM32 内部集成了可配置的上拉/下拉电阻（约 40kΩ），把引脚配成输入时可以选择接上其中之一，让引脚在没有外部驱动时有一个确定的默认电平。

```
上拉输入:                下拉输入:
    VDD                       │
     │                        │
  [~40kΩ]                     │
     │                     [~40kΩ]
     ├─── 引脚                 ├─── 引脚
     │                        │
    默认高电平              GND 默认低电平
```

最典型的应用是按键检测。按键一端接 GND、另一端接引脚并配成上拉输入，没按时上拉电阻把引脚保持在高电平，按下时引脚被直接接到 GND 变成低电平：

```c
// 按键一端接 GND，另一端接引脚（配置为上拉输入）
// 未按下 → 上拉电阻使其保持高电平
// 按下   → 引脚被直接接到 GND → 低电平
if (HAL_GPIO_ReadPin(KEY_GPIO_Port, KEY_Pin) == GPIO_PIN_RESET) {
    // 按键被按下（低电平有效）
}
```

实践中上拉输入远比下拉输入常见，这背后有清晰的工程逻辑。大量控制信号默认采用低电平有效（Active-Low），典型的如片选（CS）、中断（INT）、复位（RST）：正常工作时它们被上拉电阻保持为高，需要触发时任一设备把它拉低，而且上电瞬间引脚自然被上拉到高，保证芯片不会在上电过程中被误触发。开漏输出也天然只能拉低，在开漏总线（如 I2C）的另一端，接收设备通常也配成上拉输入，与开漏"低电平 + 释放高阻"两种状态正好配合。下拉输入也有其用武之地：有些信号约定为高电平有效（如某些使能引脚 EN），用下拉输入保证默认关闭，避免上电时意外使能。归根结底，选上拉还是下拉，取决于默认状态应该是什么——让默认值符合系统的安全状态。

## 3. HAL 库 GPIO API

日常操作 GPIO 主要就是三个函数：写引脚、翻转引脚、读引脚。

```c
// 写引脚（输出高/低电平）
HAL_GPIO_WritePin(GPIOA, GPIO_PIN_5, GPIO_PIN_SET);    // PA5 = 高电平
HAL_GPIO_WritePin(GPIOA, GPIO_PIN_5, GPIO_PIN_RESET);  // PA5 = 低电平

// 翻转引脚电平
HAL_GPIO_TogglePin(GPIOA, GPIO_PIN_5);

// 读引脚（返回当前电平状态）
GPIO_PinState state = HAL_GPIO_ReadPin(GPIOA, GPIO_PIN_5);
```

引脚的模式、上下拉、初始电平等属性一般不手写，而是在 CubeMX 里配置好，可选项如下：

| 配置项 | 可选值 | 含义 |
|--------|--------|------|
| GPIO mode | Input / Output | 输入或输出模式 |
| GPIO Pull-up/Pull-down | No pull / Pull-up / Pull-down | 内部上下拉 |
| GPIO output level | Low / High | 初始输出电平 |
| Maximum output speed | Low / Medium / High / Very High | 输出翻转速度 |
| User Label | 自定义名称 | 给引脚起名，生成宏定义 |

配置完成后 CubeMX 会生成对应的初始化代码到 `gpio.c`，可以看到它先使能 GPIO 时钟，再把上面这些属性填进 `GPIO_InitTypeDef` 结构体交给 `HAL_GPIO_Init()`：

```c
void MX_GPIO_Init(void)
{
    GPIO_InitTypeDef GPIO_InitStruct = {0};

    __HAL_RCC_GPIOA_CLK_ENABLE();   // 使能 GPIOA 时钟

    HAL_GPIO_WritePin(GPIOA, GPIO_PIN_5, GPIO_PIN_RESET);  // 初始低电平

    GPIO_InitStruct.Pin = GPIO_PIN_5;
    GPIO_InitStruct.Mode = GPIO_MODE_OUTPUT_PP;       // 推挽输出
    GPIO_InitStruct.Pull = GPIO_NOPULL;               // 无上下拉
    GPIO_InitStruct.Speed = GPIO_SPEED_FREQ_LOW;      // 低速
    HAL_GPIO_Init(GPIOA, &GPIO_InitStruct);
}
```

## 4. GSRL 中的 GPIO 使用场景

GSRL 里 GPIO 有两类典型用法，正好对应前面讲的低电平有效和外部中断。

第一类是 [SPI](./09-SPI通信原理.md) 的片选信号（CS）。SPI 通信中主设备通过 CS 引脚（低电平有效）选择从设备，GSRL 中 BMI088 IMU 的加速度计和陀螺仪各用一个独立的 CS 引脚，配置信息记录在 `dvc_imu.hpp` 里：

```cpp
// dvc_imu.hpp 中 BMI088 的 SPI 配置
struct SPIConfig {
    SPI_HandleTypeDef *hspi;      // SPI 句柄
    GPIO_TypeDef *csGPIOGroup;    // CS 引脚 GPIO 组
    uint16_t csGPIOPin;           // CS 引脚编号
};
```

通信时拉低 CS 选中从设备，传完数据再拉高 CS 释放：

```c
// 拉低 CS → 选中从设备
HAL_GPIO_WritePin(csGPIOGroup, csGPIOPin, GPIO_PIN_RESET);
// ... SPI 传输数据 ...
// 拉高 CS → 释放从设备
HAL_GPIO_WritePin(csGPIOGroup, csGPIOPin, GPIO_PIN_SET);
```

第二类是外部中断引脚。IMU 的 INT1 引脚接到 STM32 的外部中断线，数据准备好时触发[中断](./04-中断与NVIC.md)，中断处理里再交给 HAL 分发到回调：

```c
// stm32f4xx_it.c 中的外部中断处理
void EXTI4_IRQHandler(void)
{
    HAL_GPIO_EXTI_IRQHandler(INT1_ACCEL_Pin);  // HAL 处理，最终调用回调
}
```

配置这类引脚时，需要在 CubeMX 中把 GPIO mode 设为 `External Interrupt Mode with Rising/Falling edge`。

## 5. 实践要点

把前面的原理落到实际选型上，常见场景的做法可以归纳如下：

| 场景 | 做法 | 原因 |
|------|------|------|
| 驱动 LED | 推挽输出 + 串联限流电阻 | LED 需要主动驱动电流 |
| 按键检测 | 上拉输入（按键接 GND） | 避免悬空，无按键时稳定为高 |
| I2C 通信 | 开漏输出 + 外部上拉 4.7kΩ | 多设备共享，避免总线冲突 |
| 读取传感器就绪信号 | 上拉输入 + 外部中断 | 悬空时电平不确定，中断误触发 |
| 控制小电流负载 | GPIO → 三极管 → 负载 | MCU 引脚驱动能力有限（约 8mA），三极管适合小电流开关 |
| 控制大电流负载 | GPIO → MOSFET → 负载 | 大电流场景下 MOSFET 导通电阻低、发热小，比三极管更合适 |

表格里反复提到 MCU 引脚驱动能力有限，这一点值得单独说清楚，因为它直接决定了能不能用 GPIO 去驱动负载。STM32 的单个 IO 引脚通常只能提供约 8~25mA 的驱动电流（不同型号略有差异），整颗芯片所有 IO 的总电流也有上限（比如不超过 150mA）。这不是厂商偷工减料，而是三方面的物理限制。首先是芯片散热：几十个引脚同时输出数十毫安，焦耳热（I²R）会让芯片温度急剧上升，封装的热传导能力有限，没有强散热手段芯片就可能过热损坏。其次是键合线（Bond Wire）的瓶颈：芯片内部的硅片（Die）通过极细的金线或铝线（直径约 25μm）连到外部引脚，这些细丝载流能力有限，电流过大会像保险丝一样熔断。最后是意外短路时的自我保护：调试时探针误触、杜邦线误插是家常便饭，有限的驱动电流意味着短路时不会立刻烧毁引脚，给排查留出了窗口。

正因如此，凡是要控制电机、继电器、电磁阀、大功率 LED、加热丝这类大电流负载，绝对不能用 GPIO 直接驱动，必须通过三极管、MOSFET 或专用驱动芯片来"放大"电流，GPIO 只负责输出微弱的控制信号。

## 6. 小结

| 要点 | 说明 |
|------|------|
| 高电平 | 接近 3.3V，逻辑 `1` |
| 低电平 | 接近 0V，逻辑 `0` |
| 推挽输出 | 可主动输出高/低电平，驱动能力强 |
| 开漏输出 | 只能拉低，需外部上拉电阻实现高电平 |
| 上拉输入 | 内部电阻拉到 VDD，默认为高电平 |
| 下拉输入 | 内部电阻拉到 GND，默认为低电平 |
| HAL API | `WritePin` / `ReadPin` / `TogglePin` |
