# 定时器与 PWM

定时器是 MCU 里最灵活的外设之一，既能测量时间，也能产生精确的波形。它的用途看似分散——计时、测频、生成 PWM，但根子上是同一个东西：一个不停计数的计数器。抓住这一点，各种模式都能顺理成章地推出来。在机器人控制里，PWM 直接驱动[舵机](./07-舵机与电机.md)，也是理解[电机](./07-舵机与电机.md)控制的基础。

## 1. 定时器的本质是计数器

定时器的核心是一个自动递增（或递减）的计数器，每收到一个[时钟](./02-时钟树与总线架构.md)脉冲就加 1。既然时钟频率是固定的，计数值也就精确地对应着流逝的时间——数了多少个脉冲，就等于过了多少个时钟周期。这就是它既能计时又能测时的根本原因。

```
时钟 (84MHz)  ──→  ┌──────────┐  ──→  计数值 (CNT)
                   │  计数器   │       0 → 1 → 2 → 3 → ... → ARR → 0 → ...
                   └──────────┘
                        │
                   预分频器 (PSC)
                   ÷(PSC+1)

实际计数频率 = 时钟频率 / (PSC + 1)
```

围绕这个计数器，有几个关键寄存器：

| 参数 | 寄存器 | 含义 |
|------|--------|------|
| **预分频器** (Prescaler) | PSC | 对时钟进行分频，决定计数频率 |
| **自动重装载值** (Auto-Reload) | ARR | 计数的上限值，到达后归零（或减到零后重置） |
| **计数值** (Counter) | CNT | 当前的计数值（运行时不断变化） |
| **比较值** (Compare) | CCRx | 与 CNT 比较，相等时翻转输出（用于 PWM） |

定时周期就由 PSC 和 ARR 共同决定：

```
定时器时钟 = 总线时钟 / (PSC + 1)
溢出时间   = (ARR + 1) / 定时器时钟

举例：
总线时钟 = 84MHz (APB1 Timer Clock)
PSC = 8399     → 计数频率 = 84MHz / 8400 = 10kHz
ARR = 9999     → 溢出时间 = 10000 / 10kHz = 1 秒

即：该定时器每 1 秒溢出一次（产生一次更新中断）
```

之所以用 PSC 和 ARR 两级分频而不是一个参数，是为了把"分辨率"和"周期"这两件事分开调。PSC 决定计数的粒度，也就是每个计数值代表多长时间；ARR 决定一个周期总共有多少个计数值。两者互不干扰，才能同时满足不同需求。举两个例子：50Hz 舵机 PWM 要求 1μs 的精细分辨率（1ms~2ms 的脉宽范围只有 1000μs 可调），用 PSC=83 把 84MHz 降到 1MHz（每步 1μs），再用 ARR=19999 给出 20ms 周期；而 20kHz 电机 PWM 不需要 μs 级分辨率，却需要更多的占空比档位来平滑调节，于是 PSC=0 不分频，ARR=8399 提供 8400 级步长。如果只有一个参数，要么分辨率不够（舵机抖动），要么周期不对（频率偏移），顾此失彼。

## 2. 定时器的三大工作模式

### 2.1 基本定时——产生周期性中断

最简单的用法是让定时器溢出时触发[中断](./04-中断与NVIC.md)，在中断里执行周期性任务。系统时基就是这么来的：

```c
// CubeMX 配置：
// TIM7 作为系统时基，PSC=83, ARR=999  →  1ms 中断一次

void HAL_TIM_PeriodElapsedCallback(TIM_HandleTypeDef *htim)
{
    if (htim->Instance == TIM7) {
        HAL_IncTick();  // 系统 tick 计数 +1
    }
}

// FreeRTOS 的延时依赖这个 tick (HAL_GetTick())
vTaskDelay(100);  // 延时 100ms，基于 TIM7 的 1ms tick
```

### 2.2 输入捕获——测量外部信号的频率或脉宽

定时器可以在外部引脚发生边沿变化时，把当前计数值"捕获"下来。两次捕获之差乘以计数周期，就是脉冲宽度。

```
输入信号: ──┐     ┌──────────────────────┐     ┌──
            │     │                      │     │
            └─────┘                      └─────┘
            ↑                             ↑
       捕获计数值 C1                  捕获计数值 C2

脉宽 = (C2 - C1) × (1 / 计数频率)
```

典型用途是测量遥控接收机的 PWM 信号脉宽，1ms~2ms 对应 -100%~+100% 油门。

### 2.3 输出比较与 PWM 生成

这是定时器最核心的控制输出模式。原理是拿计数值 CNT 和比较值 CCR 作比较，据此翻转输出电平：CNT 小于 CCR 时输出一种电平，CNT 到达或超过 CCR 时输出反相。ARR 决定 PWM 的周期，CCR 与 ARR 的比值就是占空比。

```
    CNT ↑
    ARR ┤         ┌─────┐         ┌─────
        │        ╱       ╲       ╱
    CCR ┤───────╱─────────╲─────╱────────
        │      ╱           ╲   ╱
      0 ┤─────╱─────────────╲─╱──────────→ 时间
        │
    输出 ┤     ┌──────────┐   ┌──────────
        │     │          │   │
        └─────┘          └───┘
        ←─高电平─→←低电平→
```

- **CNT < CCR**：输出高电平（或低电平，取决于 PWM 模式）
- **CNT ≥ CCR**：输出反相
- **ARR**：PWM 周期
- **CCR / ARR**：占空比（Duty Cycle）

占空比从 0% 到 100% 连续可调，可以用来控制舵机角度、电机转速、LED 亮度等等。

这里有个值得想一想的问题：既然要控制这些模拟量，为什么用 PWM 而不是直接输出一个模拟电压？原因在于 MCU 是纯数字器件，要产生真正的模拟电压得靠数模转换器（DAC），而 DAC 在硅片上占面积、成本高，通用 MCU 通常只有一两个通道；PWM 只需要一个定时器加一个 GPIO 引脚，任何带定时器的引脚都能输出，一个 MCU 动辄几十路。更关键的是效率：电机驱动板上的 MOS 管在完全导通或完全关断时损耗最低，若用线性电压让它停在"半开"状态，大量功率会变成热量耗散在管子上，轻则效率骤降，重则烧板。PWM 让 MOS 管始终在全开和全关之间切换，靠调节开关时间的比例等效出不同的平均电压，既高效又精准。

## 3. HAL 库的 PWM 配置

在 CubeMX 里配置 PWM 的步骤是：选一个定时器的某个通道（如 TIM1_CH1），把 `Clock Source` 设为 `Internal Clock`，`Channel1` 选 `PWM Generation CH1`，设置 Prescaler 和 Counter Period（即 ARR），最后在 GPIO 页面确认对应引脚已被自动配置。

代码侧的操作主要是启动、设占空比、停止三步：

```c
// 启动 PWM 输出（CubeMX 生成的初始化之后手动调用）
HAL_TIM_PWM_Start(&htim1, TIM_CHANNEL_1);

// 设置占空比
// CCR 的取值范围是 0 ~ ARR（对应 0% ~ 100%）
__HAL_TIM_SET_COMPARE(&htim1, TIM_CHANNEL_1, 500);  // 如果 ARR=999，即 50% 占空比

// 停止 PWM
HAL_TIM_PWM_Stop(&htim1, TIM_CHANNEL_1);
```

## 4. PWM 在机器人中的典型应用

### 4.1 驱动舵机

舵机是靠 PWM 的脉宽而非占空比来控制角度的，不同脉宽对应不同角度：

```
脉宽        角度（典型值）
─────────────────────────
0.5ms       0°
1.0ms       45°
1.5ms       90°  (中位)
2.0ms       135°
2.5ms       180°
```

对应的 PWM 配置（周期 20ms，即 50Hz）：

```c
// TIM 配置：PSC=167, ARR=19999 → 计数频率=1MHz，周期=20ms
// 脉宽映射：1ms = 1000 计数值，2ms = 2000 计数值
__HAL_TIM_SET_COMPARE(&htim, channel, 1500);  // 1.5ms → 90° 中位
```

舵机对 50Hz（20ms 周期）的要求来自航模时代的 RC 伺服协议标准，历史上标准舵机都按 50Hz 脉宽调制信号设计。输出 100Hz 或 200Hz 时，部分舵机的内部解码电路只认 20ms 帧间隔，会完全不响应。20ms 的周期也给了舵机内部的 PID 控制环足够的反应时间：舵机收到脉宽指令后，内部电机要驱动齿轮组转到目标位置，再由电位器反馈实际角度，这个闭环需要几毫秒。周期太短（比如 5ms）舵机还没转到位就被下一条指令覆盖，会抖动甚至失控。只有明确标注"高频舵机"的型号才能缩短周期（如 2.5ms，即 400Hz），普通的 SG90、MG996R 等请坚持 50Hz。

### 4.2 驱动直流电机（通过电调）

无刷电机通常通过电调（ESC）驱动。电调接收标准的 PWM 信号（1ms~2ms 脉宽），把它转换成电机的三相驱动信号。

### 4.3 控制 LED 亮度

调整 PWM 占空比可以实现"模拟调光"——人眼会自然平均掉快速闪烁的光，于是看到的是稳定的不同亮度：

```c
// 呼吸灯效果
for (int duty = 0; duty <= ARR; duty++) {
    __HAL_TIM_SET_COMPARE(&htim, channel, duty);
    HAL_Delay(2);
}
```

## 5. 互补 PWM 与死区

驱动电机的半桥或 H 桥时，需要两路互补的 PWM 让上下管交替导通，并且在切换的瞬间必须插入一段死区（Dead Time）——上下管同时导通会把电源直接短路，也就是所谓的"直通"。

```
      ┌──┐  ┌──┐  ┌──┐  ┌──
上管   │  │  │  │  │  │  │
      ┘  └──┘  └──┘  └──┘
           ┌──┐  ┌──┐  ┌──┐
下管       │  │  │  │  │  │
      ─────┘  └──┘  └──┘  └──
         ←死区→              ← 上下管都关断，避免直通
```

STM32 的高级定时器（TIM1、TIM8）内置死区发生器，只需配置 `BreakAndDeadTime` 参数：

```c
sBreakDeadTimeConfig.DeadTime = 42;  // 死区时间（单位与时钟频率有关）
HAL_TIMEx_ConfigBreakDeadTime(&htim1, &sBreakDeadTimeConfig);
```

死区不是可选项而是必需项，根源在于 MOS 管有物理上的关断延迟。MOS 管从收到关断信号到真正完全关闭，需要几十纳秒到几微秒，具体取决于型号和驱动电路。在互补 PWM 的半桥里，上管和下管串联在电源正极和地之间；如果上管还没完全关断下管就导通，电流就会从上管直通下管形成短路。MOS 管导通内阻只有毫欧级，24V 电源经两个导通内阻短路，瞬间电流可达几十甚至上百安培，结果就是管子乃至整块驱动板瞬间烧毁。死区就是为这段关断延迟留出的安全间隙，在这个短暂窗口里上下管全部关断，确保一个彻底关闭后另一个才打开。死区值需要按实际 MOS 管折中：太短有直通风险，太长则电流波形畸变、电机转矩脉动增大。典型值上，低速开关 MOS 管约 1~2μs，高速 GaN MOS 管可小到 100ns。

GSRL 中 `CubeMX_BSP/Inc/tim.h` 和 `CubeMX_BSP/Src/tim.c` 包含了定时器的初始化代码，实际工程里 TIM1、TIM8 这类高级定时器常用于电机 PWM 控制。

## 6. 小结

| 要点 | 说明 |
|------|------|
| 定时器本质 | 计数器 + 预分频 + 自动重装载 |
| 三大模式 | 基本定时、输入捕获、输出比较（PWM） |
| PWM 参数 | 周期 = ARR/计数频率，占空比 = CCR/ARR |
| 舵机控制 | 脉宽 0.5~2.5ms，周期 20ms |
| 死区 | 互补 PWM 必选，防止上下管直通 |
| HAL API | `PWM_Start` / `SET_COMPARE` / `PWM_Stop` |
