# 多态（Polymorphism）

继承让子类复用父类的接口，但真正让面向对象强大的，是"同一个接口、根据对象的实际类型表现出不同行为"这件事。这就是多态（Polymorphism）。它解决的问题是：当我们用一个统一的方式操作一堆不同类型的对象时，如何让每个对象各自跑自己的逻辑。在 C++ 中，多态依靠虚函数（virtual function）实现。

## 从静态绑定到动态绑定

先看不用多态会怎样。在一个继承体系里，如果函数不是虚函数，通过父类指针调用它时，永远调到的是父类的版本：

```cpp
class Filter {
public:
    float update(float input) { return input; }  // 非虚函数——默认行为：直通
};

class KalmanFilter : public Filter {
public:
    float update(float input) { /* 卡尔曼滤波逻辑 */ return m_state; }
private:
    float m_state = 0.0f;
};

class MovingAverage : public Filter {
public:
    float update(float input) { /* 滑动平均逻辑 */ return m_avg; }
private:
    float m_avg = 0.0f;
};

// 使用场景：用一个数组存放不同类型的滤波器
Filter* filters[2];
filters[0] = new KalmanFilter();
filters[1] = new MovingAverage();

filters[0]->update(10.0f);  // 调用 Filter::update，而非 KalmanFilter::update！
filters[1]->update(10.0f);  // 同样调用 Filter::update
```

原因在于，编译器在编译期就根据指针的静态类型（这里是 `Filter*`）定死了要调用哪个函数，这叫静态绑定（Static Binding）。它压根不看指针实际指向的对象究竟是什么类型，因此子类重写的逻辑完全被绕过了。

给函数加上 `virtual` 关键字，情况就变了。函数调用不再在编译期定死，而是推迟到运行期，根据对象的真实类型来决定：

```cpp
class Filter {
public:
    virtual float update(float input) { return input; }  // 虚函数
    virtual ~Filter() = default;                          // 虚析构函数（见下文）
};
```

此后同样的两行调用，行为就对了：

```cpp
filters[0]->update(10.0f);  // 运行期发现是 KalmanFilter → 调用 KalmanFilter::update
filters[1]->update(10.0f);  // 运行期发现是 MovingAverage → 调用 MovingAverage::update
```

没有 `virtual` 就是静态绑定，看指针类型；有 `virtual` 就是动态绑定，看对象类型。这个关键字就是多态的开关。

## 虚函数的相关关键字

虚函数的基本语法就是在成员函数前加 `virtual`。它可以有默认实现，也可以写成纯虚函数（末尾 `= 0`，见下文）：

```cpp
class BTNode {
public:
    virtual ~BTNode() = default;              // 虚析构函数
    virtual BTStatus tick() = 0;              // 纯虚函数
    virtual void reset() {}                   // 普通虚函数（有默认实现）
};
```

在子类中重写虚函数时，建议在函数后加上 `override`。它一方面向读者明确表达"这是在重写基类的虚函数"，另一方面让编译器检查函数签名是否和基类完全一致——签名对不上时会直接报编译错误，而不是悄悄变成一个新函数：

```cpp
class SequenceNode : public BTNode {
public:
    BTStatus tick() override {   // 明确标注"这是重写"
        for (auto& child : m_children) {
            if (child->tick() == BTStatus::FAILURE)
                return BTStatus::FAILURE;
        }
        return BTStatus::SUCCESS;
    }
};
```

与之相对，如果某个虚函数不希望再被子类重写，可以加 `final`；`final` 也能用在整个类上，表示这个类不允许被继承：

```cpp
class CriticalNode : public BTNode {
public:
    BTStatus tick() override final { /* ... */ }  // 子类不能再重写 tick()
};

class FinalFilter final : public Filter {
    // 此类不能被继承
};
```

## 多态的本质：虚函数表

多态不是魔法，它由编译器通过虚函数表（vtable）实现。每个含有虚函数的类都会多出一个隐藏的虚函数表指针（vptr），指向一张存着函数指针的表：

```
Filter 类（有虚函数）:
┌─────────────────┐
│  vtable 指针    │ ──→ ┌──────────────────────┐
│  (隐藏成员)     │     │ &Filter::update      │
├─────────────────┤     │ &Filter::~Filter     │
│  其它成员变量    │     └──────────────────────┘
└─────────────────┘

KalmanFilter 类（重写了 update）:
┌─────────────────┐
│  vtable 指针    │ ──→ ┌───────────────────────────┐
│  (隐藏成员)     │     │ &KalmanFilter::update     │  ← 指向子类版本
├─────────────────┤     │ &KalmanFilter::~KalmanFilter│
│  m_state        │     └───────────────────────────┘
│  m_covariance   │
│  ...            │
└─────────────────┘
```

当通过基类指针调用虚函数时，程序先通过对象找到 vptr，再通过 vptr 找到 vtable，然后在 vtable 里查出对应的函数指针并调用。这一整套查表动作发生在运行期，因此比直接调用多了一次指针解引用的开销。在嵌入式实时系统里这点开销通常可以接受，但心里要清楚它的存在。

## 重载、隐藏与重写

这三个词长得像，本质却完全不同，最简单的区分办法是看它们是否发生在继承中。

重载（Overloading）不涉及继承，发生在同一个类内部：函数名相同、参数列表不同。编译器在编译期就能根据实参选出对应版本，和多态没有关系：

```cpp
class Logger {
public:
    void log(const char* msg);          // 版本 1
    void log(const char* msg, int id);  // 版本 2：参数不同 → 重载
};

Logger logger;
logger.log("error");         // 调用版本 1
logger.log("error", 404);   // 调用版本 2
```

隐藏（Hiding）发生在继承关系中：只要子类定义了一个与父类同名的函数，无论参数是否相同、是否为虚函数，父类的同名函数就被整个遮挡：

```cpp
class Base {
public:
    void show(int x) { /* ... */ }
};

class Derived : public Base {
public:
    void show() { /* ... */ }  // 名字相同 → 隐藏了 Base::show(int)
};

Derived d;
d.show();       // 调用 Derived::show
// d.show(10);  // ❌ 编译错误：Base::show(int) 被隐藏了
```

想解除遮挡，用 `using` 声明把父类的同名函数引入子类作用域即可：

```cpp
class Derived : public Base {
public:
    using Base::show;          // 将 Base 中所有名为 show 的函数引入
    void show() { /* ... */ }  // 子类版本
};

Derived d;
d.show();      // 调用 Derived::show
d.show(10);    // 调用 Base::show(int) —— 不再被隐藏
```

重写（Override）才是多态的核心。它同样发生在继承关系中，子类重新实现父类的虚函数，前提是父类的函数必须是虚函数，且子类的函数签名要与父类完全一致：

```cpp
class Filter {
public:
    virtual float update(float input) { return input; }
};

class KalmanFilter : public Filter {
public:
    float update(float input) override { /* 子类实现 */ return 0.0f; }
};

Filter* f = new KalmanFilter();
f->update(10.0f);  // 动态绑定 → 调用 KalmanFilter::update
```

三者放在一起对比，差别一目了然：

| 概念 | 发生位置 | 需要 virtual | 绑定方式 | 与多态的关系 |
|------|---------|:-----------:|---------|-------------|
| 重载 Overloading | 同一个类内部 | 否 | 编译期（静态） | 无关 |
| 隐藏 Hiding | 继承关系中 | 否 | 编译期（静态） | 无关 |
| 重写 Override | 继承关系中 | 是 | 运行期（动态） | 多态的实现方式 |

## 纯虚函数与抽象类

有时基类根本给不出有意义的默认实现，比如"滤波器"这个概念本身并不对应某种具体算法。这时可以把函数声明为纯虚函数，在末尾写上 `= 0`，表示它没有实现、子类必须重写：

```cpp
class BTNode {
public:
    virtual BTStatus tick() = 0;  // = 0 表示纯虚函数——没有实现，子类必须重写
};
```

包含纯虚函数的类称为抽象类（Abstract Class），它不能直接实例化，只能被继承：

```cpp
BTNode node;  // ❌ 编译错误：BTNode 是抽象类，不能实例化

class SequenceNode : public BTNode {
public:
    BTStatus tick() override { /* ... */ }  // 必须实现
};

SequenceNode seq;  // ✅ 可以实例化——它实现了所有纯虚函数
```

抽象类的作用是定义接口规范：它告诉所有派生类"你必须实现这些函数"，却不规定具体怎么实现。GSRL 的行为树、滤波器、控制器体系大量依赖这种约定。

## 父类指针转子类：static_cast 与 dynamic_cast

在多态体系里，经常需要把父类指针转回子类指针，好去访问子类特有的成员。C++ 提供了两种转换，取舍在于安全与速度。

`static_cast` 在编译期完成转换，不做任何检查。它快，但不安全——如果指针实际指向的并不是目标类型，结果是未定义行为。适合类型确定的场景：

```cpp
Filter* f = new KalmanFilter();
KalmanFilter* kf = static_cast<KalmanFilter*>(f);  // 直接转换，不检查
```

`dynamic_cast` 则在运行期做类型检查，转换失败时返回 `nullptr`，因此可以先判断再使用。代价是它依赖虚函数表、要求基类有虚函数，并且带有运行期开销：

```cpp
Filter* f = getSomeFilter();  // 不确定具体类型

KalmanFilter* kf = dynamic_cast<KalmanFilter*>(f);
if (kf) {
    // 转换成功，可以安全使用 KalmanFilter 特有的成员
    kf->setProcessNoise(0.1f);
} else {
    // 转换失败，f 不是 KalmanFilter
}

MovingAverage* ma = dynamic_cast<MovingAverage*>(f);
if (ma) {
    ma->setWindowSize(10);
}
```

| 特性 | `static_cast` | `dynamic_cast` |
|------|--------------|----------------|
| 安全性 | 不安全 | 安全（失败返回 nullptr） |
| 速度 | 快 | 较慢（运行期类型检查） |
| 依赖虚函数 | 否 | 是 |
| 使用场景 | 类型确定 | 类型不确定，需要安全转换 |

> GSRL 中偏好 `static_cast`，因为嵌入式环境追求性能且类型关系通常在编译期已明确。行为树节点的类型转换会借助 `static_cast` 完成。

## 虚析构函数

多态里有一个容易被忽视却很关键的点。当通过基类指针删除派生类对象时，如果析构函数不是虚函数，就只会调用基类的析构函数，派生类那部分资源被悄悄漏掉：

```cpp
class Filter {
public:
    ~Filter() { /* 释放 Filter 的资源 */ }  // 非虚析构函数——危险！
};

class KalmanFilter : public Filter {
public:
    ~KalmanFilter() { /* 释放矩阵内存 */ }  // 这个析构函数不会被调用！
private:
    float* m_buffer = new float[100];       // 这块内存泄漏了
};

Filter* f = new KalmanFilter();
delete f;  // 只调用 Filter::~Filter()，不调用 KalmanFilter::~KalmanFilter()
```

解决办法是把基类的析构函数声明为 `virtual`：

```cpp
class Filter {
public:
    virtual ~Filter() = default;  // 虚析构函数——正确！
};
```

这样 `delete f` 会通过虚函数表找到 `KalmanFilter::~KalmanFilter()`，先调用子类析构、再调用父类析构，资源被完整释放。由此得到一条通用原则：一个类只要被设计成基类（会被继承），它的析构函数就应该是 `virtual`，哪怕函数体是空的。

## 与 GSRL 的关系

多态在 GSRL 中无处不在。行为树里，`BTNode` 是抽象基类，定义纯虚函数 `tick()`，`BTSequence`、`BTSelector`、`BTCondition` 等子类各自重写它实现不同的行为逻辑，运行时通过基类指针数组遍历所有节点，多态机制保证每个节点执行自己的逻辑。控制器里，`Controller` 是抽象基类，`SimplePID` 通过重写 `controllerCalculate()` 给出具体控制算法，上层代码只依赖 `Controller*` 接口，不关心背后是哪种控制器。滤波器同理，`Filter<T>` 定义滤波接口，`KalmanFilter`、`MovingAverage` 各自实现，控制器持有一个 `Filter<fp32>*` 成员，靠多态就能在不改控制器代码的前提下切换滤波器。

嵌入式约束下，GSRL 用多态时也有几条讲究：虚函数数量尽量少，以减小 vtable 体积；避免在中断服务例程（ISR）里做 `dynamic_cast` 这类带运行期开销的操作；接口类（如 `BTNode`）保持简洁，纯虚函数数量控制在个位数。

多态的前提是继承（详见《面向对象编程.md》）。而多态体系中常见的"只复制指针、不复制数据"的语义，则由移动语义来高效实现（详见《移动语义.md》）。
