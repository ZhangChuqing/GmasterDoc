# 面向对象编程（OOP）

程序规模一小，代码怎么写都能跑；一旦规模膨胀，真正的难题是如何让代码依然易于理解、修改和复用。面向对象编程（Object-Oriented Programming，OOP）就是为这个问题而生的一种组织方式，它的核心思路是把数据和操作数据的函数绑定在一起。

## 从面向过程到面向对象

在面向过程的写法里，数据和函数是分开的。数据放在一个结构体里，操作它的函数散落在各处：

```cpp
// 面向过程：数据与操作分离
struct RobotState {
    float x, y;       // 位置
    float vx, vy;     // 速度
    float heading;    // 朝向
};

void moveForward(RobotState* robot, float distance) {
    robot->x += distance * cos(robot->heading);
    robot->y += distance * sin(robot->heading);
}

void rotate(RobotState* robot, float angle) {
    robot->heading += angle;
}
```

项目小的时候这样写没问题，但代码一多，几个毛病就暴露出来：任何函数都能随手改动 `RobotState` 的内部数据，没有任何保护；新增一种机器人类型时，一堆相关函数都得跟着改；数据和操作之间的关系不写在代码里，读起来要靠猜。

面向对象把数据和操作数据的方法封装在一起，形成一个"类"（Class）：

```cpp
// 面向对象：数据与操作绑定
class Robot {
public:
    void moveForward(float distance) {
        m_x += distance * cos(m_heading);
        m_y += distance * sin(m_heading);
    }

    void rotate(float angle) {
        m_heading += angle;
    }

    float getX() const { return m_x; }
    float getY() const { return m_y; }

private:
    float m_x = 0.0f, m_y = 0.0f;
    float m_vx = 0.0f, m_vy = 0.0f;
    float m_heading = 0.0f;
};
```

类是蓝图，对象是照着蓝图造出来的具体实例。一份 `Chassis` 类的定义能创建出 `chassis1`、`chassis2` 等多个底盘对象，它们结构相同，但各自的数据互不干扰。

## 类与对象

类的基本结构就是把成员变量和成员函数写在一起，再用访问控制符划分内外：

```cpp
class Chassis {
public:    // 公有成员——外部可以访问
    void setSpeed(float vx, float vy) {
        m_vx = vx;
        m_vy = vy;
    }

    float getSpeedX() const { return m_vx; }  // const 表示不修改成员变量

private:   // 私有成员——只有类内部可以访问
    float m_vx = 0.0f;
    float m_vy = 0.0f;
    float m_omega = 0.0f;
};
```

`public` 和 `private` 是访问控制符，决定哪些代码能碰到类的成员，这是封装（Encapsulation）在语法上的落脚点。C++ 一共有三种访问级别，区别在于对类内部、子类和外部各自开放到什么程度：

| 修饰符 | 类内部访问 | 子类访问 | 外部访问 |
|--------|-----------|---------|---------|
| `public` | ✓ | ✓ | ✓ |
| `protected` | ✓ | ✓ | ✗ |
| `private` | ✓ | ✗ | ✗ |

封装的做法是把数据设成 `private`，只通过 `public` 接口提供受控的访问。外部代码碰不到内部状态，就无法随意篡改，bug 自然少了一大类来源。

创建对象有栈上和堆上两种方式，成员的访问方式也随之不同：

```cpp
int main() {
    Chassis chassis;              // 在栈上创建对象
    chassis.setSpeed(1.0f, 0.5f); // 通过公有接口操作

    // chassis.m_vx = -1.0f;      // ❌ 编译错误：m_vx 是 private 成员

    Chassis* pChassis = new Chassis();  // 在堆上创建对象
    pChassis->setSpeed(2.0f, 0.0f);     // 指针用 -> 访问成员
    delete pChassis;                     // 手动释放堆上对象
}
```

在 GSRL 等工程里，类的声明通常放在 `.hpp` 头文件，成员函数的实现放在 `.cpp` 源文件。这么分开是为了控制编译依赖、加快增量编译：

```cpp
// chassis.hpp —— 声明
class Chassis {
public:
    void setSpeed(float vx, float vy);  // 只声明，不实现
    float getSpeedX() const;

private:
    float m_vx = 0.0f, m_vy = 0.0f;
};

// chassis.cpp —— 定义（实现）
void Chassis::setSpeed(float vx, float vy) {
    m_vx = vx;
    m_vy = vy;
}

float Chassis::getSpeedX() const {
    return m_vx;
}
```

`Chassis::` 是作用域限定符，告诉编译器这个函数属于 `Chassis` 类。

## 构造函数与析构函数

对象诞生时要初始化，消亡时要收尾，这两件事分别交给构造函数和析构函数，它们都由编译器在恰当的时机自动调用，不用手动去喊。

构造函数（Constructor）在对象创建时自动调用，名字和类名相同，没有返回值：

```cpp
class SimplePID {
public:
    // 带参数的构造函数
    SimplePID(PIDMode mode, float kp, float ki, float kd)
        : m_mode(mode)              // 初始化列表
        , m_kp(kp)
        , m_ki(ki)
        , m_kd(kd)
    {}

private:
    PIDMode m_mode;
    float m_kp, m_ki, m_kd;
    float m_integral = 0.0f;       // 类内初始值（C++11）
};

// 使用
SimplePID pid(PIDMode::PID_POSITION, 1.0f, 0.1f, 0.05f);
```

上面冒号后面那串写法叫初始化列表，它在对象构造时一步到位地初始化成员。与之相对的是在函数体里赋值，那要先默认构造成员再赋新值，等于走了两步：

```cpp
// 初始化列表（推荐）
SimplePID(PIDMode mode, float kp)
    : m_mode(mode), m_kp(kp)     // 直接初始化，一步到位
{}

// 函数体内赋值（不推荐）
SimplePID(PIDMode mode, float kp) {
    m_mode = mode;               // 先默认构造，再赋值 = 两步
    m_kp = kp;
}
```

对 `int`、`float` 这类基本类型，两种写法差别微乎其微；但对 `std::string`、自定义类等复杂类型，初始化列表省掉了一次多余的默认构造加赋值，值得优先使用。另外要留意默认构造函数的规则：类里一个构造函数都没写时，编译器会自动补一个无参的默认构造函数；可一旦你定义了任意一个带参构造函数，编译器就不再自动补了，此时若还想要无参构造，得自己手动写出来。

析构函数（Destructor）在对象生命周期结束时自动调用，负责释放资源，名字是 `~类名()`，无参数无返回值：

```cpp
class DataLogger {
public:
    DataLogger(size_t size) {
        m_buffer = new float[size];  // 在堆上分配
        m_size = size;
    }

    ~DataLogger() {
        delete[] m_buffer;           // 释放堆上内存
    }

private:
    float* m_buffer;
    size_t m_size;
};
```

析构的时机取决于对象在哪：栈上的对象离开作用域时自动析构，堆上的对象在 `delete` 时析构。还有一个容易混的点，用 `new[]` 分配的资源必须用 `delete[]` 释放，不能和 `delete` 混用。

对象被拷贝时，还要决定"怎么拷贝"。默认行为是逐成员拷贝，也就是浅拷贝，这对持有指针的类是危险的：

```cpp
DataLogger a(100);
DataLogger b = a;  // 浅拷贝：a.m_buffer 和 b.m_buffer 指向同一块内存！
// a 和 b 析构时会重复 delete 同一块内存 → 崩溃
```

两个对象的指针指向同一块内存，各自析构时都要 `delete` 它，同一块内存被释放两次，程序崩溃。正确的做法是定义深拷贝，各自分配独立的内存再复制数据：

```cpp
class DataLogger {
public:
    // 拷贝构造：分配新内存，复制数据
    DataLogger(const DataLogger& other)
        : m_size(other.m_size)
    {
        m_buffer = new float[m_size];
        for (size_t i = 0; i < m_size; ++i) {
            m_buffer[i] = other.m_buffer[i];
        }
    }

    // 拷贝赋值：释放旧内存，分配新内存，复制数据
    DataLogger& operator=(const DataLogger& other) {
        if (this != &other) {         // 防止自赋值
            delete[] m_buffer;         // 释放旧内存
            m_size = other.m_size;
            m_buffer = new float[m_size];
            for (size_t i = 0; i < m_size; ++i) {
                m_buffer[i] = other.m_buffer[i];
            }
        }
        return *this;
    }

    ~DataLogger() { delete[] m_buffer; }
private:
    float* m_buffer = nullptr;
    size_t m_size = 0;
};
```

由此有一条经验，叫三法则（Rule of Three）：一个类只要需要自定义析构函数、拷贝构造函数、拷贝赋值运算符三者中的任意一个，往往三个都得写，因为它们本质上都在处理同一份资源的管理。

> GSRL 的嵌入式环境中，许多类通过静态分配避免了动态内存，因此不需要自定义拷贝/析构。但如果类内部使用了 `new`，就必须正确处理三法则。

## 继承

继承让一个类复用另一个类的接口和实现，表达的是"是一个（is-a）"的关系。基类定义共同的接口，派生类各自给出具体实现：

```cpp
// 基类：过滤器接口
class Filter {
public:
    virtual ~Filter() = default;
    virtual float update(float input) = 0;  // 纯虚函数，详见《多态.md》
};

// 派生类：卡尔曼滤波器 "是一个" 过滤器
class KalmanFilter : public Filter {
public:
    float update(float input) override {
        // 卡尔曼滤波的具体实现
        return m_state;
    }
private:
    float m_state = 0.0f;
};

// 派生类：移动平均滤波器 "是一个" 过滤器
class MovingAverage : public Filter {
public:
    float update(float input) override {
        // 移动平均的具体实现
        return m_average;
    }
private:
    float m_average = 0.0f;
};
```

继承本身也分公有、保护、私有三种，区别在于父类成员在子类中的可见性会被压到哪一级：

```cpp
class Child : public Parent    {};  // 公有继承：父类 public → 子类 public（最常见）
class Child : protected Parent {};  // 保护继承：父类 public → 子类 protected
class Child : private Parent   {};  // 私有继承：父类 public → 子类 private
```

| 继承方式 | 父类 `public` 在子类中变为 | 父类 `protected` 在子类中变为 | 使用场景 |
|---------|--------------------------|-----------------------------|---------|
| `public` | `public` | `protected` | "是一个"关系（标准多态） |
| `protected` | `protected` | `protected` | 复用实现但不暴露接口 |
| `private` | `private` | `private` | 纯实现复用（"用...实现"） |

GSRL 中绝大多数继承是 `public` 继承。如果只是想复用代码而非表达"是一个"关系，优先考虑组合，也就是把对象作为成员变量，而不是继承。

子类对象的构造要先把父类那部分建好，再建自己的成员。因此子类构造函数会在初始化列表里先调用父类构造函数：

```cpp
class Filter {
public:
    Filter(float cutoff) : m_cutoff(cutoff) {}
protected:
    float m_cutoff;
};

class KalmanFilter : public Filter {
public:
    KalmanFilter(float cutoff, float q)
        : Filter(cutoff)    // 先调用父类构造函数
        , m_q(q)            // 再初始化子类成员
    {}

private:
    float m_q;
};
```

完整的构造顺序是父类先行，接着按声明顺序初始化子类成员，最后执行子类构造函数体；析构顺序则完全相反，从子类析构函数体开始，到子类成员，再到父类。

## 静态成员

前面的成员都属于某个具体对象，各自一份。静态成员则属于类本身，所有对象共享同一份：

```cpp
class Chassis {
public:
    static int getInstanceCount() { return s_instanceCount; }

    Chassis()  { s_instanceCount++; }
    ~Chassis() { s_instanceCount--; }

private:
    static int s_instanceCount;  // 声明
};

int Chassis::s_instanceCount = 0;  // 定义（必须在类外）
```

静态成员存储在静态存储区（详见《内存.md》），生命周期贯穿整个程序运行。在 GSRL 中，它常用于单例模式、全局配置这类场景。

## 类内类型定义

GSRL 代码里常把枚举和类型别名定义在类的内部：

```cpp
class Chassis {
public:
    enum ChassisMode : uint8_t {
        CHASSIS_NO_FORCE = 0,
        FOLLOW_GIMBAL,
        SPINNING
    };

    void setMode(ChassisMode mode) { m_mode = mode; }

private:
    ChassisMode m_mode = CHASSIS_NO_FORCE;
};

// 使用
Chassis chassis;
chassis.setMode(Chassis::FOLLOW_GIMBAL);  // 通过类名访问
```

这样做既避免了污染全局命名空间，也清楚地表明这个模式枚举归属于 `Chassis` 类。

## this 指针

每个非静态成员函数内部都藏着一个隐式的 `this` 指针，指向正在调用该函数的那个对象。它平时可以省略不写，但在需要返回对象自身时很有用：

```cpp
class Chassis {
public:
    Chassis& setSpeed(float vx) {
        this->m_vx = vx;   // this-> 可以省略
        return *this;       // 返回对象自身的引用（链式调用）
    }
private:
    float m_vx;
};

chassis.setSpeed(1.0f).setOmega(0.5f);  // 链式调用
```

返回 `*this` 让每次调用都交回对象本身，于是可以把多个操作串成链式调用。

## 与 GSRL 的关系

面向对象在 GSRL 中被广泛使用。`BTNode` 是所有行为树节点的基类，`BTComposite`、`BTAction` 等都继承自它；`Controller` 是控制器接口，`SimplePID` 通过公有继承实现该接口；`Filter<T>` 是滤波器基类，`KalmanFilter`、`MovingAverage` 等派生类各自实现滤波算法；`Chassis`、`Gimbal` 则是机器人子系统类，封装各自的状态与行为。

受嵌入式环境约束，GSRL 的类设计遵循几条约定：优先使用静态分配或栈上分配，减少堆上的 `new`/`delete`；成员变量在声明时就赋予类内初始值，降低未初始化风险；通过 `private` 保护内部状态，只暴露必要的 `public` 接口；用枚举类定义模式而非魔数（magic number）。

继承解决的是代码复用的问题，但它没有解决"同一接口、不同行为"的问题——那是多态的领域，详见《多态.md》。
